# 用一個帳務系統學會 Rust

> 一份以「真實應用場景」貫穿全書的 Rust 教材。
> 每一章都從一個業務需求出發，先回答 **Why（為什麼需要這個語言特性）**，
> 再說明 **What（這個特性到底是什麼）**，最後 **How（在我們的系統裡怎麼用）**。

## 貫穿全書的場景：`ledger` 小額支付帳本

想像你加入了一間新創公司，負責重寫公司的「小額支付帳本系統」。
這個系統要做的事情很單純，但一點都不能出錯：

1. 讀入每天數十萬筆的交易紀錄（存款、提款、轉帳）
2. 維護每個帳戶的餘額，拒絕不合法的交易（例如餘額不足、帳戶不存在）
3. 產生日報、月報，供財務對帳
4. 最後對外提供 API，讓其他服務即時查詢與入帳

舊系統是用動態語言寫的，曾經發生過三次嚴重事故：

- 浮點數誤差讓某個帳戶多出 0.01 元，對帳對不起來，財務加班三天
- 多執行緒同時更新同一帳戶，餘額被「蓋掉」，一筆入帳憑空消失
- 某個 `null` 沒檢查，結算批次在凌晨三點崩潰，隔天早上才被發現

這三個事故，恰好對應 Rust 最擅長解決的三類問題：**型別安全、資料競爭、空值處理**。
這就是本書選擇這個場景的原因。整本書，我們會從一個只能印出一筆交易的小程式開始，
一步一步把它長成一個多執行緒、有 HTTP API、有完整測試的服務。

## 範例程式碼

每一章的完整程式碼放在 `code/chNN-*/`，都是獨立可執行的 Cargo 專案：

```bash
cd code/ch06-errors
cargo run
cargo test
```

第 8 章以後，程式碼會演進成同一個 `ledger` crate，每章在前一章的基礎上增加功能。
建議邊讀邊打，不要只複製貼上；Rust 的學習曲線主要來自「和編譯器對話」，
自己打錯、看編譯器怎麼說、再修好，是最有效的學習方式。

## 適合誰

- 寫過任何一種程式語言（Python、Java、Go、JavaScript 皆可），想認真學 Rust 的人
- 聽過「所有權」「借用檢查器」但始終不懂為什麼需要它們的人
- 想知道 Rust 在後端、金融、系統服務裡「實際怎麼用」而不只是語法的人

不需要 C/C++ 背景。需要手動管理記憶體的概念會在用到時解釋。

## 環境需求

- Rust stable（本書以 1.80 以上為準，使用 2021 edition）
- 任何編輯器，建議搭配 rust-analyzer

安裝方式見 [第 1 章](book/01-啟程-第一筆交易.md)。
