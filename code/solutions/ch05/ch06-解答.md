## 練習 1：AccountFrozen

```rust
struct Account { id: u32, balance: Money, frozen: bool }

enum LedgerError {
    AccountFrozen(u32),
    // ...
}

fn debit(&mut self, id: u32, amount: Money) -> Result<(), LedgerError> {
    let acct = self.find_mut(id)?;
    if acct.frozen {
        return Err(LedgerError::AccountFrozen(id));
    }
    // ...
}
```

檢查放在 `debit` 而不是 `apply`：提款與轉帳來源都走 `debit`，一處檢查兩處生效；`credit` 不檢查，所以凍結帳戶仍可收款。
測試要涵蓋四種情況：凍結帳戶提款（拒）、作為轉帳來源（拒）、作為轉帳目的（允）、存款（允）。

## 練習 2：ParseError

```rust
#[derive(Debug, PartialEq, Eq)]
enum ParseError {
    MissingField { line: String, expected: usize, got: usize },
    BadNumber { field: &'static str, value: String },
    UnknownKind(String),
}

let num = |field: &'static str, s: &str| -> Result<i64, ParseError> {
    s.parse::<i64>().map_err(|_| ParseError::BadNumber { field, value: s.to_string() })
};
let amount = Money(num("amount", parts[2])?);
```

`map_err` 把標準庫的 `ParseIntError` 轉成我們的 `BadNumber`，並**加上欄位名稱**。這是比 `Box<dyn Error>` 好的地方：原本的訊息只有「invalid digit found in string」，現在是「欄位 amount 不是數字："abc"」。

錯誤型別帶上下文（哪一行、哪個欄位、拿到什麼值）是好錯誤訊息的全部秘訣。

## 練習 3：main 回傳 Result

```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let txs: Vec<Transaction> = raw.iter().map(|l| parse_line(l)).collect::<Result<_, _>>()?;
    // ...
    Ok(())
}
```

`collect::<Result<Vec<_>, _>>()` 把一串 `Result` 收成一個：任何一個 `Err` 就整體 `Err`，`?` 讓 `main` 直接結束並印出錯誤。

兩種策略：

| | 全有或全無（這題） | 壞的跳過並記錄（第 6 章原版） |
|---|---|---|
| 適合 | **互動式工具**：使用者立刻看到錯、修正、重跑 | **夜間批次**：一行壞資料不能讓整晚結算停擺 |
| 風險 | 一筆壞資料擋住全部 | 壞資料被忽略，沒人看日誌就沒人知道 |

批次程式通常要求：跳過的筆數超過某個比例（例如 1%）時整體失敗，兩種策略的折衷。
