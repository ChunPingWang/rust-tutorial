# 機器學習學習路徑　第 0 章　總覽：Rust 在機器學習裡的位置

> **場景**：風控團隊看了第 13 章的規則引擎後說：「規則是人寫的，詐欺份子會學。我們有過去兩年標記好的詐欺交易，能不能讓系統自己學出『什麼樣的交易可疑』？」
> 這條學習路徑用同一個帳本資料，從矩陣運算開始，一路做到一個能在第 15 章的 API 裡即時給出「這筆交易可疑機率」的模型。

## 先說清楚：Rust 不是 Python 的替代品

機器學習的日常是 Python：探索資料、試模型、畫圖、調參數。這部分 Rust 做不好，也不該做。
Rust 在 ML 的位置是**Python 做完實驗之後的事**：

| 階段 | 主流工具 | Rust 的角色 |
|---|---|---|
| 探索、實驗、訓練 | Python（PyTorch、scikit-learn、pandas） | 偶爾：訓練資料的前處理管線（polars 比 pandas 快 10 倍） |
| **推論部署** | Python 服務 + 大量記憶體 | **強項**：單一執行檔、低延遲、低記憶體、無 GIL，直接嵌進業務服務 |
| **邊緣裝置** | C++ | **強項**：沒有 Python runtime 的地方（嵌入式、瀏覽器 Wasm、手機） |
| **效能核心** | C++/CUDA | 寫給 Python 呼叫的擴充模組（PyO3），tokenizers、polars、safetensors 都是這樣 |
| 資料管線 | Spark、pandas | polars、datafusion、arrow：大量資料的 ETL |

對我們的帳本：模型可以用 Python 訓練，但**打分要在過帳的路徑上即時發生**，每筆交易多幾毫秒都是成本。這是 Rust 的場景。

但這條路徑裡我們會**用 Rust 做完整個流程**，包括訓練。原因是教學：自己用 ndarray 寫一次梯度下降，你會真正懂模型在做什麼，之後不管用什麼框架都不會把它當黑盒子。

## 需要的前置知識

- 本教材第 1 到 9 章（所有權、借用、struct、enum、錯誤處理、迭代器、trait）。ML 套件的 API 大量使用 trait 與泛型
- 第 12 章（外部套件）：ML 全靠 crate
- 第 15 章（async/axum）：ML-5 需要
- 數學：高中程度的向量與矩陣、「導數是斜率」的直覺。路徑裡用到的公式都會解釋，不需要事先懂

不需要 Python 或 ML 背景。有的話，每章末有「對照 scikit-learn / PyTorch」小節。

## Rust ML 生態地圖（2026）

| 類別 | crate | 定位 |
|---|---|---|
| 矩陣 | `ndarray` | NumPy 的對應物，所有東西的基礙 |
| 傳統 ML | `linfa` | scikit-learn 的對應物：回歸、分類、分群、降維 |
| 深度學習 | `candle` | Hugging Face 出品，推論為主，API 像 PyTorch，支援 CPU/CUDA/Metal |
| 深度學習 | `burn` | 另一個框架，訓練為主，後端可換（wgpu、tch、candle） |
| 深度學習 | `tch` | PyTorch C++ 的綏定，功能最完整但要帶 libtorch |
| 推論 | `ort` | ONNX Runtime 綏定，跑任何框架匯出的模型 |
| 推論 | `tract` | 純 Rust 的 ONNX/TensorFlow 推論，適合嵌入式 |
| DataFrame | `polars` | pandas 的對應物，快很多，有 Python 綁定 |
| 權重格式 | `safetensors` | Hugging Face 的權重檔格式，取代 pickle |
| 隨機 | `rand`、`rand_distr` | 分佈取樣 |
| 統計 | `statrs`、`ndarray-stats` | 分佈、檢定、描述統計 |
| LLM | `candle-transformers`、`llama.cpp` 綁定、`mistral.rs` | 在 Rust 裡跑語言模型 |

本路徑用 ndarray、linfa、candle、safetensors。其他的在 ML-5 討論何時該換。
