# ML-2　從零實作：異常偵測與邏輯回歸

> **場景**：風控團隊其實有兩個問題。
> 第一，新上線的產品線**還沒有**詐欺標記，但他們現在就想知道哪些交易可疑。
> 第二，舊產品線有兩年標記，他們想要一個「可疑機率」，而且要能解釋為什麼。
> 這一章不用任何 ML 套件，用 ndarray 寫兩個模型。目的不是取代套件，是**知道套件在做什麼**。

## Why：為什麼要自己寫一次

用 scikit-learn 三行就能訓練邏輯回歸。但不知道它在做什麼的人會：

- 不知道為什麼要標準化（梯度下降對尺度敏感）
- 不知道 threshold 是可以調的（`predict()` 預設 0.5，但那是任意的）
- 不知道 3% 的正例為什麼讓模型「全部猜正常」（損失函數被負例主導）
- 看到權重不知道怎麼解釋

邏輯回歸的數學只有三行，自己寫一次大概 60 行 Rust，之後所有分類模型的概念（損失、梯度、正則化、類別不平衡、threshold）都通了。

## What：兩種學習

### 無監督：沒有答案，找「不一樣的」

假設：正常交易很多、長得都差不多；詐欺很少、長得不一樣。那麼「離正常中心有多遠」就是異常分數。

**z-score 距離**：特徵標準化後，每筆交易是 9 維空間的一個點，正常交易聚在原點附近。距離原點的歐氏距離：

```rust
pub fn zscore_anomaly(x: &Array2<f64>) -> Array1<f64> {
    x.mapv(|v| v * v).sum_axis(Axis(1)).mapv(f64::sqrt)
}
```

一行。問題是它假設特徵彼此獨立。`log_amount` 與 `amount_to_balance` 相關 0.56，一筆大額交易會在兩個維度同時偏離，被「重複計算」。

**Mahalanobis 距離**：考慮相關性，d² = xᵀ Σ⁻¹ x，Σ 是共變異數矩陣。等於先把資料「轉到特徵彼此獨立的座標系」再算距離。
程式碼用 Cholesky 分解（Σ = LLᵀ）避免直接求逆矩陣：解 Lz = x，則 d² = ‖z‖²。40 行，不需要線性代數套件。

### 監督：有答案，學一條線

**邏輯回歸**：

```
p = σ(x·w + b)          σ(t) = 1 / (1 + e⁻ᵗ)，把任何實數壓到 (0, 1)
```

`x·w + b` 是一條線（9 維空間裡是一個超平面），`σ` 把「離線多遠」變成機率。訓練就是找 `w` 和 `b`。

**損失函數**：二元交叉熵。預測 p 與真實 y 的差距：

```
L = −[y ln p + (1−y) ln(1−p)]
```

y=1 時 L = −ln p，p 越接近 1 損失越小；y=0 時反過來。

**梯度下降**：損失對 w 的梯度剛好是

```
∂L/∂w = Xᵀ(p − y) / n
```

非常乾淨（這是為什麼邏輯回歸配交叉熵是經典組合）。每一步把 w 往梯度反方向走一小步：

```rust
let p = self.predict_proba(x);
let residual = &p - y;
let grad_w = x.t().dot(&residual) / n + &self.weights * self.l2;
self.weights = &self.weights - &(grad_w * self.learning_rate);
```

**L2 正則化**：梯度多加 `l2 * w`，把權重往 0 拉，防止過度擬合。

**類別不平衡**：詐欺只佔 3%，不處理的話模型發現「全猜正常」損失就很低。解法是給正例加權：

```rust
let sample_w = y.mapv(|v| if v >= 0.5 { self.pos_weight } else { 1.0 });
let residual = (&p - y) * &sample_w;
```

`pos_weight = 5` 讓一筆詐欺的錯誤等於五筆正常的錯誤。

### 評估：準確率是陷阱

詐欺 3%，全部猜正常準確率 97%。要看的是：

| 指標 | 定義 | 業務意義 |
|---|---|---|
| **precision** | 判為詐欺的裡面，真的詐欺的比例 | 低 = 誤殺多，客戶被打擾 |
| **recall** | 真的詐欺裡面，被抓到的比例 | 低 = 漏網多，錢丟了 |
| **F1** | precision 與 recall 的調和平均 | 兩者的折衷 |
| **ROC AUC** | 隨機抽一正一負，正例分數較高的機率 | 不依賴 threshold，適合比較模型 |

precision 與 recall 是**對立的**：threshold 調低抓更多（recall 升）但誤殺更多（precision 降）。**threshold 不是模型的參數，是業務的決定。**

### 無監督結果

```
AUC  z-score 異常分數：0.983
AUC  Mahalanobis 距離：0.976
Mahalanobis top 5%     precision 0.672  recall 0.707  F1 0.689   (TP 41 FP 20 FN 17 TN 1122)
```

**沒有用任何標記**，AUC 就有 0.98。把分數最高的 5% 標為可疑，抓到七成詐欺，誤殺 20 筆正常。
對沒有標記的新產品線，這是合理的起點：先用它篩出可疑交易給人工審核，審核結果就變成標記，幾個月後就能訓練監督模型。

這個資料集裡 z-score 比 Mahalanobis 略好，因為合成資料的詐欺本來就在多個獨立方向偏離。真實資料不一定。

### 監督結果

```rust
let mut model = LogisticRegression::new(9);
model.learning_rate = 0.3;
model.epochs = 400;
model.pos_weight = 5.0;
let losses = model.fit(&xtr, &train.y);
```

```
損失：epoch 0 = 0.6931，epoch 50 = 0.1250，最後 = 0.0641
AUC  邏輯回歸：0.995
```

epoch 0 的損失 0.6931 = ln 2，是「什麼都不知道、猜 0.5」的損失。持續下降代表有在學。看損失曲線是檢查訓練有沒有問題的第一步：不降 = 學習率太小或有 bug；震盪 = 學習率太大。

不同 threshold：

```
thr=0.3   precision 0.724  recall 0.948   (TP 55 FP 21 FN 3)
thr=0.5   precision 0.867  recall 0.897   (TP 52 FP 8  FN 6)
thr=0.7   precision 0.923  recall 0.828   (TP 48 FP 4  FN 10)
thr=0.9   precision 1.000  recall 0.724   (TP 42 FP 0  FN 16)
```

同一個模型，四種業務策略。信用卡公司會選 0.3（寧可打電話確認），B2B 轉帳可能選 0.7（誤攔一筆大額付款的代價很高）。

### 權重可以解釋

```
log_amount          +0.993
amount_to_balance   +0.712
is_withdraw         +0.704
velocity_24h        +0.695
amount_vs_acct      +0.607
hour_cos            +0.585
is_night            +0.468
bias                -4.346
```

因為特徵已標準化，權重可以直接比大小。全部是正的：每個特徵越大越可疑，符合設計。`bias = −4.3` 代表「所有特徵都平均時」p = σ(−4.3) ≈ 1.3%，接近詐欺的基礎率。
這張表可以直接拿去跟風控人員對：「模型認為金額最重要，其次是掏空程度和提款，時段反而沒那麼重要」，他們會告訴你對不對。**可解釋性是邏輯回歸在金融業仍然廣泛使用的原因**，監管機關會要求你解釋為什麼拒絕一筆交易。

### 漏網的告訴你下一步

```
p=0.467  Withdraw  8254 元  hour 21  詐欺
p=0.466  Withdraw  2191 元  hour 1   詐欺
p=0.325  Transfer 10065 元  hour 14  詐欺
```

漏掉的是「看起來正常」的詐欺：白天、金額不大。邏輯回歸是線性模型，它只能學「每個特徵各自加多少分」，學不到**交互作用**：「深夜 **且** 連續 **且** 新對象」的組合效果。這是 ML-4 神經網路的動機。

另一個下一步是更好的特徵（ML-1 練習 1 的 `is_new_counterparty`）。實務上**改特徵的投資報酬率通常比換模型高**。

## 對照 scikit-learn

```python
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler().fit(X_train)
model = LogisticRegression(class_weight={0: 1, 1: 5}, C=1/1e-3).fit(scaler.transform(X_train), y_train)
p = model.predict_proba(scaler.transform(X_test))[:, 1]
```

sklearn 用 L-BFGS 而不是梯度下降，收斂更快更穩；`C` 是 L2 的倒數。概念完全相同。ML-3 用 linfa 做同一件事。

## 回顧

- 無監督異常偵測：距離正常中心多遠。沒標記時的起點，也是產生標記的工具
- 邏輯回歸 = 一條線 + sigmoid；交叉熵損失；梯度 Xᵀ(p−y)/n；L2 防過擬合；正例加權處理不平衡
- 準確率無意義；看 precision/recall/F1/AUC；threshold 是業務決定
- 標準化後的權重可以解釋，金融業需要這個
- 線性模型抓不到交互作用；先改特徵，再換模型

## 練習

1. 把 `pos_weight` 改成 1.0 重跑，比較 thr=0.5 的 recall。再改成 20.0。觀察 precision/recall 的移動。
2. 把 `learning_rate` 改成 3.0，印出前 20 個 epoch 的損失。發生什麼事？改成 0.01 呢？
3. 實作 mini-batch 梯度下降：每個 epoch 把資料切成 64 筆一批，每批更新一次。比較收斂速度（達到相同損失需要的 epoch 數）。
4. 加一個 `l1` 正則化項（梯度加 `l1 * sign(w)`）。L1 會把不重要的權重壓到剛好 0，相當於自動選特徵。哪些特徵被壓掉了？
5. 實作 precision-recall 曲線：對 threshold 從 0.01 到 0.99 每 0.01 一步，印出 (precision, recall)。找出 precision ≥ 0.9 時最高的 recall。
