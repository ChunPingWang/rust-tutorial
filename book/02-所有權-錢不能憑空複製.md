# 第 2 章　所有權：錢不能憑空複製

> **場景**：交易要有備註欄（例如「十月薪資」「ATM 提款」）。
> 備註建立後要交給帳本保存。問題來了：交出去之後，建立它的那段程式還能不能用它？
> 如果能，那到底是誰負責這筆資料？

## Why：為什麼需要所有權

### 其他語言怎麼做

記憶體裡的資料（例如一個字串）總得有人負責釋放，否則就是記憶體洩漏。各語言的做法：

- **C/C++**：你自己 `malloc`/`free`。忘了 free 是洩漏；free 兩次是崩潰；free 之後還用叫 use-after-free，是資安漏洞的最大來源之一。
- **Java / Python / Go / JS**：垃圾回收（GC）。執行期有一個背景程序追蹤誰還在用哪塊記憶體，沒人用就回收。
  安全，但有成本：GC 暫停會讓延遲抖動，而且你永遠不確定記憶體什麼時候真的釋放。

對帳本系統：C 的風險我們承受不起，GC 的延遲抖動在結算高峰時又很惱人。有沒有第三條路？

### Rust 的第三條路

Rust 問了一個問題：**如果我們在編譯期就知道每塊記憶體什麼時候不再被使用，是不是就能自動插入 free，既不需要 GC，又不會出錯？**

答案是可以，條件是：**每個值在任何時刻只有一個擁有者（owner）**。
擁有者離開作用域，值就被釋放。因為只有一個擁有者，釋放只會發生一次，不會重複、不會遺漏。

這條規則有一個很直覺的類比：**錢**。
一筆 250 元的交易紀錄交給帳本之後，原本建立它的地方就不該再有一份，否則帳會多出 250 元。
所有權就是編譯器幫你確保「帳不會憑空多出來」。

## What：所有權的三條規則

1. Rust 中每個值都有一個**擁有者**
2. 同一時間只能有**一個**擁有者
3. 擁有者離開作用域時，值被**釋放（drop）**

### 堆疊與堆積

要理解「哪些型別會有所有權問題」，需要知道資料存在哪裡：

- **堆疊（stack）**：大小在編譯期就知道的資料，例如 `i64`、`bool`、`char`。存取極快，離開作用域自動彈出。
- **堆積（heap）**：大小在執行期才知道、或可能成長的資料，例如 `String`、`Vec`。
  堆疊上只放一個「指向堆積的指標 + 長度 + 容量」。

```
堆疊                         堆積
┌──────────────────┐        ┌───────────────────┐
│ memo: String     │        │ "十月薪資"         │
│   ptr ───────────┼───────►│                   │
│   len = 12       │        └───────────────────┘
│   cap = 12       │
└──────────────────┘
```

所有權規則真正管的是**堆積**上的資料。堆疊上的小東西複製一份不痛不癢，堆積上的資料複製要配置新記憶體，Rust 不會偷偷幫你做。

### Move：移動

```rust
let memo = String::from("十月薪資");
let memo_in_ledger = memo;      // 所有權移動
println!("{memo}");             // 編譯錯誤！
```

編譯器的訊息：

```
error[E0382]: borrow of moved value: `memo`
 --> src/main.rs:4:15
  |
2 |     let memo = String::from("十月薪資");
  |         ---- move occurs because `memo` has type `String`, which does not implement the `Copy` trait
3 |     let memo_in_ledger = memo;
  |                          ---- value moved here
4 |     println!("{memo}");
  |               ^^^^^^ value borrowed here after move
```

讀法：`memo` 的型別 `String` 沒有實作 `Copy`，所以第 3 行的賦值是「移動」而非複製，第 4 行就不能再用它了。

`let b = a;` 在 Rust 裡**不是**複製，是把堆疊上那三個欄位（ptr/len/cap）搬到 `b`，然後把 `a` 標記為「已失效」。
堆積上的資料沒有被複製，也沒有兩個指標指著它，所以之後只會被釋放一次。

### Copy：複製

```rust
let amount: i64 = 25_050;
let amount_copy = amount;
println!("{amount} {amount_copy}");   // 都能用
```

為什麼這裡可以？因為 `i64` 實作了 `Copy` 這個 trait（特徵，第 9 章詳談）。
一個型別如果**完全存在堆疊上、複製就是逐位元拷貝**，就可以是 `Copy`。
所有整數、浮點數、`bool`、`char`、由 Copy 型別組成的 tuple 都是 Copy。
`String`、`Vec` 這類擁有堆積資料的型別不是。

判斷方式很簡單：**這個型別有沒有需要釋放的資源？有，就不能是 Copy。**

### Clone：明確的深層複製

真的需要兩份？

```rust
let memo2 = String::from("十月獎金");
let memo2_backup = memo2.clone();   // 配置新的堆積記憶體，複製內容
```

`.clone()` 是故意設計成要你明寫的。讀程式的人看到 `clone` 就知道這裡有一次記憶體配置與複製。
在 Python 裡 `b = a` 和 `b = copy.deepcopy(a)` 的成本差了幾個數量級，但語法上幾乎看不出來；Rust 讓成本看得見。

### 函式呼叫也是移動

```rust
fn record(description: String) {
    println!("已記錄：{description}");
}   // description 在這裡被釋放

let d = String::from("ATM 提款");
record(d);            // d 的所有權移進函式
// println!("{d}");   // 編譯錯誤：d 已經被移走
```

這很符合直覺：你把交易紀錄「交給」了 `record`，它用完就銷毀。如果你還想要，有兩個選擇：

1. 函式把它還給你（回傳）
2. 不要交出所有權，只「借」給它看。**這是下一章的主題，也是日常寫 Rust 最常用的方式。**

```rust
fn record_and_return(description: String) -> String {
    println!("已記錄：{description}");
    description      // 還回去
}
let d = String::from("網路轉帳");
let d = record_and_return(d);   // 變數遮蔽（shadowing）：重新綁定同名變數
```

### Drop：自動釋放

```rust
{
    let temp = String::from("暫時的備註");
    println!("{temp}");
}   // temp 在這裡被 drop，堆積記憶體歸還
```

沒有 `free`，沒有 GC。編譯器在作用域結束的地方幫你插入了釋放程式碼。
這個機制叫 RAII（Resource Acquisition Is Initialization），不只用在記憶體：檔案、網路連線、鎖，
都在擁有者離開作用域時自動關閉。第 14 章的 `Mutex` 會讓你再次看到它的好處。

### `String` 與 `&str`

這是初學者最常混淆的一對：

| | `String` | `&str` |
|---|---|---|
| 擁有資料嗎 | 是，資料在堆積上 | 否，只是指向某段 UTF-8 的「視圖」 |
| 可以成長嗎 | 可以 `push_str` | 不可以 |
| 字面值 `"abc"` 是哪個 | | 這個（存在程式的唯讀區，型別是 `&'static str`） |
| 什麼時候用 | 需要擁有、修改、長期保存 | 只是讀一下、傳參數 |

轉換：

```rust
let s: String = "abc".to_string();    // 或 String::from("abc")
let v: &str = &s;                     // 或 s.as_str()
```

經驗法則：**結構體欄位與需要保存的用 `String`；函式參數只是讀的用 `&str`**。第 3 章會解釋為什麼。

## How：在帳本裡實作

完整程式碼在 `code/ch02-ownership/`，`cargo run` 之後，把註解掉的兩行 `println!` 打開，看編譯器怎麼說。

這一章刻意沒有加新功能，因為所有權不是一個「功能」，而是你接下來寫的每一行程式都要遵守的規則。
真正的收穫是培養一個習慣：**看到一個值被賦值或傳進函式，先問「所有權去哪了？」**

一個常見的誤解要先打破：你不會一直在寫 `clone()`。
初學者遇到 moved value 錯誤時第一反應是到處加 `clone`，程式能跑但效能很差，而且學不到東西。
正確的反應是下一章的借用。本書的 `ledger` 最終版程式碼裡，`clone` 出現的次數可以用一隻手數完。

## 回顧

- 每個值有唯一擁有者，擁有者離開作用域值就被釋放。沒有 GC，沒有手動 free。
- `let b = a` 對堆積資料是**移動**，之後 `a` 不能用；對 `Copy` 型別是複製
- 需要兩份就明寫 `clone()`，成本看得見
- 傳進函式就是交出所有權，用回傳拿回來，或者（下一章）只借不給

## 練習

1. 寫 `fn make_memo(kind: &str, amount: i64) -> String`，產生像「存款 250.50 元」的備註字串。思考參數為什麼用 `&str` 而回傳用 `String`。
2. 建立一個 `(u32, String)` 的 tuple 表示 `(帳戶 ID, 持有人)`，把它賦值給另一個變數，然後試著用原變數。tuple 是不是 `Copy`？為什麼？
3. 把 `record_and_return` 改成接收兩個 `String` 並都還回來（回傳 tuple）。感受一下這種寫法有多麻煩，這就是借用存在的理由。
