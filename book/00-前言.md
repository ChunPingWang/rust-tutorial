# 第 0 章　前言：為什麼要用 Rust 重寫帳本

## 這本書的讀法

大部分的程式語言教材是「語法導向」的：第一章變數、第二章流程控制、第三章函式……
讀完之後你知道每個關鍵字怎麼寫，卻不知道什麼時候該用、為什麼語言要這樣設計。
對 Rust 來說這個問題特別嚴重，因為 Rust 有一堆其他語言沒有的概念：所有權、借用、生命週期、trait、`Send`/`Sync`。
如果只看語法，這些概念看起來像是語言在找麻煩。

本書反過來：**先有需求，才有特性**。每一章的結構都是：

1. **場景**：帳本系統遇到了一個新需求或一個 bug
2. **Why**：為什麼現有的工具解決不了，或解決得不漂亮
3. **What**：Rust 提供了什麼概念來處理這件事，它的本質是什麼
4. **How**：在我們的程式碼裡實際用起來，一步一步寫
5. **回顧與練習**：你應該帶走什麼，以及可以自己試的延伸題

你會發現 Rust 的每個「奇怪」設計，背後都有一個真實世界的 bug 在等著它。

## 我們要做什麼：`ledger`

公司的小額支付帳本系統要重寫。它的核心資料只有兩種：

- **帳戶（Account）**：有 ID、持有人、餘額
- **交易（Transaction）**：存款、提款、或兩個帳戶間的轉帳，帶有金額與時間

核心規則也很少：

- 金額一律為正，以「分」為單位的整數儲存（第 1 章會解釋為什麼）
- 提款與轉帳不能讓餘額變負
- 每一筆交易要能被追溯、重放、驗證
- 任何不合法的交易要被**拒絕**而不是讓程式崩潰

需求很小，但它會逐章長大：先是單筆交易，然後是批次檔案，然後是多執行緒結算，最後是對外 API。
每一次長大，都會逼我們用到一個新的 Rust 特性。

## 為什麼是 Rust

前言裡提到舊系統出過三次事故。讓我們看看 Rust 怎麼在**編譯期**就擋掉它們。

### 事故一：浮點數讓帳對不起來

```python
# 舊系統（Python）
balance = 0.1 + 0.2
print(balance == 0.3)   # False
```

這不是 Python 的錯，是 IEEE 754 浮點數的本質。任何語言用 `float` 存錢都會遇到。
Rust 的解法不是魔法，而是**型別系統讓你很難不小心犯錯**：我們會定義一個 `Money` 型別，
內部用 `i64` 存「分」，並且禁止它和浮點數直接運算。想加法？編譯器只接受 `Money + Money`。

### 事故二：兩個執行緒同時改餘額

```java
// 舊系統（Java）
account.balance += amount;   // 兩個執行緒同時執行，其中一次更新會消失
```

這叫資料競爭（data race），是並行程式最難除錯的 bug，因為它不一定重現。
Rust 的做法是：**沒有上鎖就不能跨執行緒修改資料，而且這是編譯錯誤**。
第 14 章你會親眼看到編譯器拒絕一段有資料競爭的程式。

### 事故三：空值沒檢查，凌晨三點崩潰

```javascript
// 舊系統（Node.js）
const account = accounts.find(a => a.id === id);
account.balance -= amount;   // account 可能是 undefined
```

Rust 沒有 `null`。「可能不存在」是一個型別 `Option<T>`，你**必須**處理它不存在的情況，否則編譯不過。
第 5 章會談。

### 所以 Rust 的核心哲學是什麼

一句話：**把執行期的錯誤搬到編譯期**。

代價是編譯器比較嚴格，你會花比較多時間讓程式編譯通過。
回報是：一旦編譯通過，整類的 bug（記憶體錯誤、資料競爭、空值）就已經不存在了。
對帳本這種「錯一次就要加班三天」的系統，這個交換非常划算。

另外三個常被提到的優點，在我們的場景裡也會用到：

- **效能**：沒有垃圾回收（GC），執行速度與 C/C++ 同等級。結算百萬筆交易時有感。
- **單一執行檔**：編譯出來就是一個檔案，部署不需要安裝執行環境。第 16 章會談。
- **套件生態**：`cargo` 與 crates.io 讓加入相依套件像 npm/pip 一樣簡單，但有鎖定檔與語意化版本的紀律。

## Rust 不擅長什麼

誠實地說：

- **學習曲線陡**：前三章的所有權與借用，是大多數人卡住的地方。本書會用帳本的比喻慢慢帶，但你還是需要時間。
- **編譯慢**：大型專案的編譯時間明顯比 Go 長。
- **寫快速原型不划算**：如果你只是要寫一個用過即丟的腳本，Python 更快。

Rust 適合「寫一次，跑很久，錯不起」的程式。帳本系統正是這種程式。

## 閱讀前的準備

- 你需要會任何一種程式語言。本書會在對比時使用 Python、Java、Go、JavaScript 的片段，看不懂某一個沒關係。
- 不需要 C/C++ 背景。「堆疊」「堆積」「指標」會在用到的時候解釋。
- 準備一個終端機和一個編輯器。下一章我們就開始裝環境。

## 名詞對照

本書的中英文對照，第一次出現時會標英文，之後以中文為主：

|---|---|---|
| 所有權 | ownership | 每個值有唯一的擁有者 |
| 借用 | borrowing | 暫時使用別人擁有的值 |
| 引用 | reference | `&T` 或 `&mut T`，借用的具體形式 |
| 生命週期 | lifetime | 引用有效的範圍 |
| 特徵 | trait | 類似介面，定義型別能做什麼 |
| 列舉 | enum | 可以帶資料的標籤聯集 |
| 模式比對 | pattern matching | `match` 等解構語法 |
| 巨集 | macro | `println!` 這種帶 `!` 的東西 |
| 套件 | crate | Rust 的編譯單位與發佈單位 |
| 模組 | module | crate 內部的命名空間 |
| 恐慌 | panic | 不可恢復的錯誤，程式中止 |
