# 第 7 章　集合與迭代器：批次處理整月交易

> **場景**：帳戶數成長到五萬個，`find` 的線性搜尋讓每晚結算要跑一小時。
> 財務同時送來一張需求清單：每帳戶月流出總額、金額最大的十筆、按日分組的筆數、餘額排名、
> 以及一個風控需求：「同一帳戶連續三筆以上提款要標記」。

## Why：為什麼需要迭代器，而不是 for 迴圈

集合的部分不用多解釋：`Vec` 是動態陣列，`HashMap` 是雜湊表，每個語言都有。這章的「Why」在迭代器。

財務那張需求清單，每一項用 `for` 迴圈都寫得出來，但你會發現程式碼長得都一樣：
建一個空容器、迴圈、條件判斷、塞進容器。真正的業務邏輯（「只要提款」「按帳戶分組」「取前十」）被淹沒在樣板裡。

迭代器讓你直接寫業務邏輯：

```rust
history.iter()
    .filter(|tx| matches!(tx.kind, TxKind::Deposit { .. }))
    .map(|tx| tx.amount.0)
    .sum()
```

讀起來就是需求本身：「歷史紀錄裡，篩出存款，取金額，加總」。

你可能會擔心效能：這麼多層呼叫，是不是比手寫迴圈慢？**不會**。Rust 的迭代器是「零成本抽象」：
編譯器會把整條鏈內聯（inline）成一個迴圈，產生的機器碼與手寫迴圈相同，有時更快（因為少了邊界檢查）。
這是 Rust 與 Python 的 generator、Java 的 Stream 的本質差異：那些在執行期有真實開銷，Rust 沒有。

## What：集合、閉包、迭代器

### 常用集合

| 型別 | 用途 | 特性 |
|---|---|---|
| `Vec<T>` | 有序列表 | 尾端新增 O(1)，索引 O(1)，搜尋 O(n) |
| `HashMap<K, V>` | key → value | 查找/插入 O(1)，**無序**，K 需要 `Hash + Eq` |
| `BTreeMap<K, V>` | 排序的 key → value | O(log n)，遍歷時 key 有序，K 需要 `Ord` |
| `HashSet<T>` / `BTreeSet<T>` | 不重複的集合 | 同上 |
| `VecDeque<T>` | 雙端佇列 | 兩端新增刪除都 O(1) |
| `String` | UTF-8 字串 | 其實是 `Vec<u8>` 加上 UTF-8 保證 |

選擇原則：預設 `Vec`。需要用 key 查找用 `HashMap`。需要按 key 順序輸出（報表按日期）用 `BTreeMap`。需要去重用 `HashSet`。

### HashMap 的 entry API

「沒有就插入預設值，有就更新」是分組統計的核心模式。不要寫 `if contains_key ... else ...`（查兩次），用 `entry`：

```rust
*map.entry(tx.day).or_insert(0) += 1;

let total = map.entry(id).or_insert(Money(0));
total.0 += amount.0;
```

`entry(k)` 回傳一個 `Entry`，`or_insert(default)` 保證有值並回傳 `&mut V`。

### 從 HashMap 同時借兩個值

第 5 章轉帳時我們無法同時拿到來源與目的的 `&mut`。`HashMap` 提供了 `get_disjoint_mut`（Rust 1.86+）：

```rust
let [Some(src), Some(dst)] = self.accounts.get_disjoint_mut([&from, &to]) else {
    return false;
};
```

它保證兩個 key 不同（相同會 panic，所以先檢查 `from != to`），回傳兩個獨立的 `&mut`。
這是標準庫替你證明「這兩個借用不會重疊」，借用規則因此放行。

### 閉包（closure）

匿名函式，可以捕捉周圍的變數：

```rust
let threshold = Money(10_000);
let is_big = |tx: &Transaction| tx.amount > threshold;   // 捕捉了 threshold
```

語法 `|參數| 表達式`，多行用 `|參數| { ... }`。參數型別通常可以省略，編譯器從用法推導。

閉包捕捉變數的方式有三種，編譯器自動選最寬鬆的：借用（`&`）、可變借用（`&mut`）、取得所有權（`move`）。
第 14 章把閉包送進執行緒時會需要明寫 `move`。

### 迭代器的三個階段

```
來源                 轉接器（lazy）                        消耗器（真正執行）
.iter()         →   .filter() .map() .take() ...     →   .sum() .collect() .count() ...
```

**轉接器是惰性的**。`history.iter().map(f)` 什麼都不會做，直到你呼叫 `sum`、`collect` 等消耗器。
這表示你可以把一條長鏈存到變數、分段組裝，沒有中間集合的開銷。

### 三種來源

| 方法 | 產生的元素 | 原集合之後 |
|---|---|---|
| `.iter()` | `&T` | 還在 |
| `.iter_mut()` | `&mut T` | 還在，內容可能被改 |
| `.into_iter()` | `T` | **被消耗**，不能再用 |

`for x in &v` 等於 `for x in v.iter()`，`for x in v` 等於 `for x in v.into_iter()`。

### 常用轉接器

| 方法 | 作用 |
|---|---|
| `map(f)` | 每個元素轉換 |
| `filter(p)` | 保留滿足條件的 |
| `filter_map(f)` | map 成 `Option`，丟掉 `None`。「轉換且可能失敗」時比 `filter + map` 好 |
| `flat_map(f)` | map 成迭代器再攤平。「一筆交易影響多個帳戶」這種一對多 |
| `enumerate()` | 附上索引 `(i, x)` |
| `zip(other)` | 兩個迭代器配對 |
| `take(n)` / `skip(n)` | 取前 n / 跳過前 n |
| `take_while(p)` / `skip_while(p)` | 條件版 |
| `chain(other)` | 接上另一個迭代器 |
| `rev()` | 反向 |
| `peekable()` | 可以偷看下一個 |
| `windows(n)`（切片方法） | 滑動視窗 |
| `chunks(n)`（切片方法） | 固定大小分塊 |

### 常用消耗器

| 方法 | 作用 |
|---|---|
| `collect()` | 收集成集合。**需要標型別**：`let v: Vec<_> = ...` 或 `.collect::<Vec<_>>()` |
| `sum()` / `product()` | 加總/乘積，也需要標型別 |
| `count()` | 數量 |
| `min()` / `max()` / `min_by_key` / `max_by_key` | 極值，回傳 `Option` |
| `fold(init, f)` | 萬用累加器 |
| `any(p)` / `all(p)` | 存在/全部 |
| `find(p)` / `position(p)` | 第一個滿足的元素/索引 |
| `partition(p)` | 分成兩個集合 |
| `for_each(f)` | 對每個執行副作用（通常直接用 `for` 更清楚） |
| `last()` / `nth(n)` | 最後/第 n 個 |

`collect` 的厲害之處：同一條鏈可以收集成 `Vec`、`HashSet`、`HashMap`（從 `(K, V)` pairs）、`String`（從 `char` 或 `&str`），只看你標的型別。
甚至能收集成 `Result<Vec<T>, E>`：一堆 `Result` 中有一個 `Err` 就整體 `Err`，全部 `Ok` 就得到 `Vec`。第 12 章讀 CSV 會用到。

### 排序

`Vec` 的排序方法：

```rust
v.sort();                                      // 需要 T: Ord，升冪
v.sort_by(|a, b| b.amount.cmp(&a.amount));     // 自訂比較，這裡是降冪
v.sort_by_key(|x| x.amount);                   // 按某個 key
v.sort_by_key(|x| std::cmp::Reverse(x.amount)); // 按 key 降冪
v.sort_unstable();                             // 不保證相等元素順序，更快
```

`f64` 沒有實作 `Ord`（因為 NaN），所以浮點數排序要用 `sort_by(|a, b| a.partial_cmp(b).unwrap())` 或 `total_cmp`。這是不用浮點數存錢的又一個小理由。

### 字串與 Unicode

`String` 是 UTF-8 bytes。`s.len()` 是 byte 數，`s[0]` 不合法。處理字元用迭代器：

```rust
"王小明".chars().count()      // 3
"王小明".len()                // 9
"王小明".chars().next()       // Some('王')
"王小明".chars().rev().collect::<String>()  // "明小王"
```

## How：帳本改用 HashMap，報表全用迭代器

完整程式碼在 `code/ch07-collections/`。

### 資料結構

```rust
struct Ledger {
    accounts: HashMap<u32, Account>,    // O(1) 查找
    history: Vec<Transaction>,          // 已過帳的交易，報表的資料來源
}
```

`apply` 現在接收 `Transaction` 的所有權（不是 `&Transaction`），因為成功的交易要 `push` 進 `history` 保存。回顧第 3 章的原則：**要存下來才接收所有權**。

### 需求一：總存款

```rust
fn total_deposits(&self) -> Money {
    let cents: i64 = self.history.iter()
        .filter(|tx| matches!(tx.kind, TxKind::Deposit { .. }))
        .map(|tx| tx.amount.0)
        .sum();
    Money(cents)
}
```

### 需求二：每帳戶流出總額

```rust
fn outflow_by_account(&self) -> HashMap<u32, Money> {
    self.history.iter().fold(HashMap::new(), |mut acc, tx| {
        let debited = match tx.kind {
            TxKind::Withdraw { account } => Some(account),
            TxKind::Transfer { from, .. } => Some(from),
            TxKind::Deposit { .. } => None,
        };
        if let Some(id) = debited {
            acc.entry(id).or_insert(Money(0)).0 += tx.amount.0;
        }
        acc
    })
}
```

`fold` 的第一個參數是初始值，閉包接收「目前累積值」與「下一個元素」，回傳新的累積值。這裡的累積值是整個 HashMap。
說實話，這個需求用 `for` 迴圈 + `entry` 一樣清楚，`fold` 不是必須的。原則：**鏈式寫法讀起來比迴圈清楚才用，否則用迴圈**。`daily_count` 就是用迴圈寫的。

### 需求三：按日分組

```rust
fn daily_count(&self) -> BTreeMap<u32, usize> {
    let mut map = BTreeMap::new();
    for tx in &self.history {
        *map.entry(tx.day).or_insert(0) += 1;
    }
    map
}
```

用 `BTreeMap` 而不是 `HashMap`，因為報表要按日期順序印。`HashMap` 的迭代順序是隨機的（每次執行都不同，這是刻意的安全設計）。

### 需求四：金額前 N

```rust
fn top_n(&self, n: usize) -> Vec<&Transaction> {
    let mut sorted: Vec<&Transaction> = self.history.iter().collect();
    sorted.sort_by(|a, b| b.amount.cmp(&a.amount));
    sorted.truncate(n);
    sorted
}
```

收集的是 `&Transaction`（借用），不是 clone。排序的是一堆指標，很便宜。

### 需求五：風控，連續三筆提款

```rust
fn rapid_withdrawals(&self) -> Vec<u32> {
    let withdraws: Vec<u32> = self.history.iter()
        .filter_map(|tx| match tx.kind {
            TxKind::Withdraw { account } => Some(account),
            _ => None,
        })
        .collect();
    withdraws.windows(3)
        .filter(|w| w[0] == w[1] && w[1] == w[2])
        .map(|w| w[0])
        .collect::<HashSet<_>>()
        .into_iter()
        .collect()
}
```

`filter_map` 一步完成「只要提款，而且只要帳戶 ID」。`windows(3)` 產生所有連續三個元素的切片。最後收集成 `HashSet` 去重，再轉回 `Vec`。

### 一對多：flat_map

```rust
fn active_accounts(&self) -> HashSet<u32> {
    self.history.iter()
        .flat_map(|tx| match tx.kind {
            TxKind::Deposit { account } | TxKind::Withdraw { account } => vec![account],
            TxKind::Transfer { from, to } => vec![from, to],
        })
        .collect()
}
```

一筆轉帳影響兩個帳戶，`map` 會得到 `Vec<Vec<u32>>`，`flat_map` 攤平成 `u32` 的串流。

## 效能筆記

- `Vec<&T>` 排序比 `Vec<T>` 排序快得多（搬指標 vs 搬整個結構），報表函式回傳借用是正確的預設
- `HashMap` 用的是防 HashDoS 的雜湊函式，比較慢。極端效能需求可以換 `FxHashMap`/`ahash`，但先量測再換
- `collect` 進中間 `Vec` 再處理，有時比一條超長鏈好讀。`rapid_withdrawals` 刻意這樣寫
- 迭代器鏈編譯後與手寫迴圈同速，**不要為了效能放棄迭代器**

## 回顧

- 預設 `Vec`，key 查找 `HashMap`，有序輸出 `BTreeMap`，去重 `HashSet`；`entry` API 做分組統計
- `iter()` 借用、`into_iter()` 消耗、`iter_mut()` 可變借用
- 轉接器惰性、消耗器觸發；`collect` 和 `sum` 要標型別
- `filter_map` 處理「轉換且可能失敗」，`flat_map` 處理「一對多」
- 鏈式寫法讀起來比迴圈清楚才用
- 字串用 `chars()`，不要 byte 索引
