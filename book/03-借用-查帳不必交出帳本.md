# 第 3 章　借用：查帳不必交出帳本

> **場景**：帳本現在有一串交易。財務要「查詢總額」「列印明細」，櫃台要「入帳」。
> 查詢顯然不該把帳本搬走再搬回來；入帳則需要修改帳本。
> 兩種需求都不想轉移所有權，但一個只讀、一個要寫。

## Why：為什麼需要借用

上一章結尾你應該已經感受到：每次呼叫函式都要把值交出去再拿回來，寫起來非常煩。
真實世界也不是這樣運作的：會計查帳是「借」帳本看一下，看完還回去，帳本的擁有者一直是公司。

但「借」會引出新問題。想像兩個人同時借帳本：

- 兩個人都只是**看**：沒問題，看幾個人都行
- 一個人在**改**、另一個人在**看**：看的人可能看到改到一半的帳，資料不一致
- 兩個人同時**改**：互相覆蓋，這就是前言的事故二

所以借用要有規則。其他語言把這個規則交給程式設計師自律（或者文件、code review）；Rust 把它寫進編譯器。

## What：引用與借用規則

### 兩種引用

| 寫法 | 名稱 | 能做什麼 |
|---|---|---|
| `&T` | 不可變引用（shared reference） | 讀 |
| `&mut T` | 可變引用（exclusive reference） | 讀和寫 |

建立引用的動作叫**借用（borrow）**。引用本身是一個指標，指向別人擁有的值；引用離開作用域時**不會**釋放被指向的值，因為它不是擁有者。

```rust
let memos = vec![String::from("十月薪資")];
let r = &memos;        // 借用
println!("{}", r.len());
// memos 還在，r 只是看了一眼
```

### 借用規則（The Borrowing Rules）

在任何時刻，對同一個值：

1. 可以有**任意多個** `&T`，**或者**
2. **恰好一個** `&mut T`

但不能同時兩者都有。

另外一條：**引用必須永遠有效**，不能指向已經被釋放的值（這是第 10 章生命週期的主題）。

就這樣。所有的借用檢查錯誤都是這兩條規則的具體化。對照剛才的三種情境：

- 多人同時看 → 多個 `&T`，允許
- 一人改一人看 → `&mut T` 與 `&T` 共存，禁止
- 兩人同時改 → 兩個 `&mut T`，禁止

這個規則有一個更專業的說法：**別名（aliasing）與可變（mutation）不能同時存在**。
這不只擋掉了多執行緒的資料競爭，也擋掉了單執行緒裡的一類 bug：一邊遍歷 Vec 一邊往裡面 push 導致的迭代器失效。
Java 會在執行期丟 `ConcurrentModificationException`，C++ 是未定義行為，Rust 是編譯錯誤。

### 可變引用實際上有多嚴格

```rust
let mut memos = vec![String::from("a")];
let first = &memos[0];          // 不可變借用開始
memos.push(String::from("b"));  // 需要 &mut memos → 編譯錯誤
println!("{first}");            // first 還在用
```

```
error[E0502]: cannot borrow `memos` as mutable because it is also borrowed as immutable
```

為什麼這是真正的 bug 而不是編譯器找麻煩？因為 `push` 可能會讓 Vec 重新配置記憶體，`first` 就會指向已經釋放的舊位置。
在 C++ 這是會讓程式隨機崩潰的經典錯誤。

### 借用的範圍：到最後一次使用為止

好消息是編譯器很聰明。借用不是「到作用域結束」，而是「到這個引用**最後一次被使用**」為止。
這個特性叫 NLL（Non-Lexical Lifetimes）。

```rust
let first = &memos[0];
println!("{first}");            // first 最後一次使用
memos.push(String::from("b"));  // OK！first 的借用已經結束
```

所以遇到借用錯誤時，第一個檢查：能不能**調整順序**，讓讀的部分先結束，再做修改。多數情況這就夠了。

### 解引用

引用是指標，要拿到它指向的值用 `*`：

```rust
let x = 5;
let r = &x;
println!("{}", *r + 1);   // 6
```

但大多時候你不需要寫 `*`。方法呼叫（`r.len()`）、比較、`println!` 都會自動解引用。
只有在賦值或算術時偶爾需要明寫。

### 切片：借用一段範圍

切片是「對連續序列中某一段的引用」：

```rust
let amounts = vec![100, 200, 300];
let all: &[i64] = &amounts;          // 整個 Vec 的切片
let tail: &[i64] = &amounts[1..];    // 從索引 1 到結尾
let mid: &[i64] = &amounts[0..2];    // 索引 0、1（不含 2）

let s = String::from("hello");
let h: &str = &s[0..1];              // 字串切片，&str 就是 String 的切片型別
```

函式參數用切片而不是 `&Vec<T>` 是慣例：`&[i64]` 可以接受 Vec、陣列、另一個切片，更通用。
同樣地，參數用 `&str` 而不是 `&String`，因為 `&String` 可以自動轉成 `&str`，反過來不行。

注意字串切片的索引是 **byte** 位置，不是字元位置。中文字在 UTF-8 裡佔 3 bytes，`&s[0..1]` 切在一個中文字中間會 panic。
處理中文時用 `.chars()` 迭代器（第 7 章）。

## How：讓帳本可查可改

完整程式碼在 `code/ch03-borrowing/`。帳本暫時用兩個平行的 Vec 表示，下一章會改成結構體。

### 只讀的操作用 `&`

```rust
fn print_ledger(memos: &[String], amounts: &[i64]) {
    println!("--- 帳本（{} 筆）---", memos.len());
    for i in 0..memos.len() {
        println!("{:<12} {:>12}", memos[i], format_money(amounts[i]));
    }
}

fn sum(amounts: &[i64]) -> i64 {
    let mut total = 0;
    for a in amounts {     // a 是 &i64
        total += *a;
    }
    total
}
```

呼叫端：

```rust
print_ledger(&memos, &amounts);
let total = sum(&amounts);
// memos、amounts 都還在
```

### 要修改的用 `&mut`

```rust
fn post(memos: &mut Vec<String>, amounts: &mut Vec<i64>, memo: &str, amount: i64) {
    memos.push(memo.to_string());
    amounts.push(amount);
}

post(&mut memos, &mut amounts, "網路轉帳", -120_050);
```

注意呼叫端也要寫 `&mut`。這是刻意的：讀程式的人看到 `&mut memos` 就知道「這個呼叫會改到 memos」，不必打開函式看。
對比 Python，`f(ledger)` 到底會不會改 `ledger` 你得看實作。

`post` 這裡參數用 `&mut Vec<String>` 而不是切片，因為切片不能 `push`（長度固定）。什麼時候用哪個：**需要改長度就用 `&mut Vec`，否則用切片。**

### 回傳引用

```rust
fn largest_memo(memos: &[String]) -> &String {
    let mut best = &memos[0];
    for m in memos {
        if m.len() > best.len() {
            best = m;
        }
    }
    best
}
```

回傳的 `&String` 借用自參數 `memos`。編譯器需要知道「回傳的引用活多久」，這裡它自動推出來了（只有一個引用參數，回傳一定借自它）。
第 10 章會談需要手動標註的情況。

### 試著弄壞它

程式裡有一段：

```rust
let biggest = largest_memo(&memos);
println!("最長的備註：{biggest}");
memos.push(String::from("利息"));
```

把 `push` 那行搬到 `println!` 之前，編譯器會報 E0502。再搬回去就好了。花一分鐘感受 NLL：**借用在最後一次使用時結束**。

再試一個：

```rust
let r1 = &mut memos;
let r2 = &mut memos;    // E0499: cannot borrow `memos` as mutable more than once at a time
r1.push(String::from("x"));
```

## 常見的初學者困惑

**Q：為什麼 `for a in amounts` 裡的 `a` 是 `&i64`？**
因為 `amounts` 是 `&[i64]`，迭代一個引用得到的是元素的引用。如果是 `for a in vec` 而 `vec` 是 `Vec<i64>`，`a` 就是 `i64`，而且 `vec` 會被消耗掉（所有權移進迴圈）。
想迭代但不消耗，寫 `for a in &vec`。

**Q：我什麼時候該用引用，什麼時候該交出所有權？**
預設用引用。只有在「這個函式要把值存起來」（例如 push 進 Vec、放進結構體）時才接收所有權。`post` 接收 `memo: &str` 卻存 `memo.to_string()`，就是「借進來，存自己的一份」。

**Q：編譯器一直說 borrowed，我是不是該到處 clone？**
不是。先試調整順序（NLL），再試縮小借用範圍（把借用放進一個小的 `{}` 區塊），最後才考慮 clone。

## 回顧

- `&T` 可以有很多個，`&mut T` 同時只能有一個，兩者不能共存
- 借用到最後一次使用為止，不是到作用域結束
- 函式參數預設用 `&`；要改用 `&mut`；要存下來才接收所有權
- 參數型別偏好 `&[T]` 與 `&str`，比 `&Vec<T>`、`&String` 通用
- 這套規則在單執行緒就擋掉迭代器失效，在多執行緒擋掉資料競爭

3. 故意寫出 E0499（兩個 `&mut`）和 E0502（`&` 和 `&mut` 共存），把編譯器的完整訊息讀一遍。
