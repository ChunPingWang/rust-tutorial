# 第 5 章　列舉與模式比對：交易不只一種

> **場景**：產品要支援「轉帳」。轉帳有來源帳戶與目的帳戶，存款與提款只有一個帳戶。
> 把兩個欄位都塞進 `Transaction` 然後讓其中一個「有時候是空的」？這正是舊系統凌晨三點崩潰的起點。
> 另外，`find_account` 找不到帳戶時要回傳什麼？

## Why：為什麼需要「帶資料的列舉」，以及為什麼沒有 null

### 問題一：不同種類的東西有不同欄位

常見的錯誤設計：

```rust
struct Transaction {
    kind: String,            // "deposit" / "withdraw" / "transfer"
    account: u32,            // 存款、提款用
    from: Option<u32>,       // 轉帳才有
    to: Option<u32>,         // 轉帳才有
}
```

問題：`kind == "transfer"` 時 `account` 是什麼？`kind == "deposit"` 時 `from` 應該是 `None`，但誰保證？
打錯字 `"trasnfer"` 編譯器也不會知道。這種「用字串標籤 + 一堆可能為空的欄位」的設計，讓非法狀態可以被表示出來，bug 只是時間問題。

Rust 的 enum 讓你說：「交易**要嘛**是存款（帶一個帳戶），**要嘛**是提款（帶一個帳戶），**要嘛**是轉帳（帶兩個帳戶）」。
沒有第四種可能，每一種的欄位都剛好是它需要的。這個概念在型別理論叫**和型別（sum type）**或**代數資料型別**，Rust 的 enum 就是它。

### 問題二：null

Tony Hoare 發明 null 之後稱它為「十億美元的錯誤」。問題不在於「值可能不存在」，這是真實需求；
問題在於**型別系統看不出來哪些值可能不存在**。Java 的 `Account` 型別，可能是帳戶也可能是 null，你只能靠文件和運氣。

Rust 的做法：「可能不存在的帳戶」和「帳戶」是**兩個不同的型別**，前者叫 `Option<Account>`。
你不能對 `Option<Account>` 呼叫 `.balance`，編譯器逼你先處理「沒有」的情況。

## What：enum、match、Option

### 定義 enum

```rust
enum TxKind {
    Deposit { account: u32 },          // 帶具名欄位
    Withdraw { account: u32 },
    Transfer { from: u32, to: u32 },
}

enum Status {
    Pending,        // 不帶資料
    Posted,
    Rejected,
}

enum Shape {
    Circle(f64),               // 帶匿名欄位（像 tuple）
    Rect(f64, f64),
}
```

每個變體（variant）可以不帶資料、帶 tuple、或帶具名欄位。建立值：

```rust
let k = TxKind::Transfer { from: 1001, to: 1002 };
let s = Status::Posted;
```

enum 也可以有 `impl` 區塊，和 struct 一樣。

### match：窮舉式模式比對

```rust
let action = match &self.kind {
    TxKind::Deposit { account } => format!("帳戶 {account} 存入"),
    TxKind::Withdraw { account } => format!("帳戶 {account} 提出"),
    TxKind::Transfer { from, to } => format!("帳戶 {from} 轉給 {to}"),
};
```

`match` 的關鍵性質：**必須窮舉**。少寫一個變體是編譯錯誤：

```
error[E0004]: non-exhaustive patterns: `&TxKind::Transfer { .. }` not covered
```

這對帳本系統極其重要。半年後有人新增 `TxKind::Fee`，所有 `match` 這個 enum 的地方全部編譯失敗，逼你一個一個去補。
在用字串標籤的設計裡，新增一種交易，忘了處理的分支會默默走進 `else`。

模式還可以：

```rust
// 合併多個分支
TxKind::Deposit { account } | TxKind::Withdraw { account } => vec![account],

// 守衛（guard）：加條件
n if n >= 10_000_000 => "大額",

// 範圍
0..=999 => "零錢",

// 忽略其餘欄位
LedgerError::InsufficientFunds { account, .. } => ...,

// 萬用
_ => "其他",

// 綁定變數同時比對
amount @ 1_000..=9_999 => println!("中額 {amount}"),
```

`match` 是表達式，每個分支的型別必須相同。

### 只關心一種情況：`if let`、`let else`、`matches!`

`match` 兩個分支其中一個是 `_ => {}` 的時候，用 `if let` 更簡潔：

```rust
if let Some(acct) = self.find_mut(id) {
    acct.balance = ...;
}
```

「不是想要的形狀就提早離開」用 `let else`（Rust 1.65+）：

```rust
let Some(acct) = self.find_mut(id) else {
    return Status::Rejected;
};
// 這裡 acct 一定有值
```

只要一個布林值用 `matches!`：

```rust
let is_transfer = matches!(tx.kind, TxKind::Transfer { .. });
```

### Option：標準庫裡的 enum

`Option` 就是一個普通的 enum，標準庫這樣定義：

```rust
enum Option<T> {
    None,
    Some(T),
}
```

`T` 是泛型參數（第 9 章），現在把 `Option<Money>` 讀成「可能有的 Money」就好。
`Some` 和 `None` 不需要寫 `Option::` 前綴，因為它們太常用了，預設匯入。

常用方法，依「你想做什麼」分類：

| 想做什麼 | 方法 | 例子 |
|---|---|---|
| 有值就轉換 | `map` | `find(id).map(\|a\| a.balance)` |
| 沒值給預設 | `unwrap_or`、`unwrap_or_else`、`unwrap_or_default` | `balance.unwrap_or(Money(0))` |
| 判斷 | `is_some`、`is_none` | `find(to).is_none()` |
| 鏈式查找 | `and_then` | `find(id).and_then(\|a\| a.nickname())` |
| 轉成 Result | `ok_or`、`ok_or_else` | 下一章 |
| 確定有值，沒有就 panic | `unwrap`、`expect("原因")` | 只在測試或「真的不可能是 None」時用 |

**`unwrap` 的使用原則**：生產程式碼裡每一個 `unwrap` 都是一個潛在的 panic。
用 `expect("為什麼這裡不可能是 None")` 代替，至少崩潰時有理由。更好的是用 `match`/`if let`/`?` 把 None 真正處理掉。

### Option<&T> 與借用

```rust
fn find(&self, id: u32) -> Option<&Account>
```

回傳 `Option<&Account>`（可能有的借用）而不是 `Option<Account>`（可能有的擁有值）。
前者零成本，後者要 clone 整個帳戶。這也呼應第 3 章：查詢不該搬走資料。

## How：用 enum 重做交易，用 Option 重做查找

完整程式碼在 `code/ch05-enums/`。

### 交易模型

```rust
#[derive(Debug, Clone, PartialEq)]
enum TxKind {
    Deposit { account: u32 },
    Withdraw { account: u32 },
    Transfer { from: u32, to: u32 },
}

#[derive(Debug, Clone)]
struct Transaction {
    id: u64,
    kind: TxKind,
    amount: Money,      // 永遠是正數了，方向由 kind 決定
    memo: String,
}
```

比起上一章「正數存款負數提款」，現在 `amount` 永遠是正的，交易的方向由型別表達。非法狀態（例如「轉帳給自己」）仍然可以表示，下一章用錯誤處理擋。

### 「這筆交易影響哪些帳戶」

```rust
fn affected_accounts(&self) -> Vec<u32> {
    match self.kind {
        TxKind::Deposit { account } | TxKind::Withdraw { account } => vec![account],
        TxKind::Transfer { from, to } => vec![from, to],
    }
}
```

這裡 `match self.kind` 沒有加 `&`，因為 `u32` 是 Copy，直接拿出來就好。如果變體裡有 `String`，就要 `match &self.kind` 避免移動。

### 查找：Option 取代 null

```rust
impl Ledger {
    fn find(&self, id: u32) -> Option<&Account> {
        for acct in &self.accounts {
            if acct.id == id {
                return Some(acct);
            }
        }
        None
    }

    fn find_mut(&mut self, id: u32) -> Option<&mut Account> {
        self.accounts.iter_mut().find(|a| a.id == id)   // 迭代器版本，第 7 章
    }

    fn balance_of(&self, id: u32) -> Option<Money> {
        self.find(id).map(|a| a.balance)
    }
}
```

### 過帳

```rust
fn apply(&mut self, tx: &Transaction) -> Status {
    if tx.amount.0 >= 10_000_000 {
        return Status::Pending;      // 大額先掛起
    }
    match &tx.kind {
        TxKind::Deposit { account } => {
            if let Some(acct) = self.find_mut(*account) {
                acct.balance = Money(acct.balance.0 + tx.amount.0);
                Status::Posted
            } else {
                Status::Rejected
            }
        }
        TxKind::Withdraw { account } => {
            let Some(acct) = self.find_mut(*account) else {
                return Status::Rejected;
            };
            if tx.amount > acct.balance {
                return Status::Rejected;
            }
            acct.balance = Money(acct.balance.0 - tx.amount.0);
            Status::Posted
        }
        TxKind::Transfer { from, to } => {
            let from_balance = match self.balance_of(*from) {
                Some(b) => b,
                None => return Status::Rejected,
            };
            if self.find(*to).is_none() || tx.amount > from_balance {
                return Status::Rejected;
            }
            if let Some(src) = self.find_mut(*from) {
                src.balance = Money(src.balance.0 - tx.amount.0);
            }
            if let Some(dst) = self.find_mut(*to) {
                dst.balance = Money(dst.balance.0 + tx.amount.0);
            }
            Status::Posted
        }
    }
}
```

三個分支刻意用了三種不同寫法（`if let`/`else`、`let else`、`match`），讓你比較。
實務上「有就做、沒有就離開」用 `let else` 最乾淨。

**轉帳分支的一個借用細節**：為什麼不能寫

```rust
let src = self.find_mut(from);
let dst = self.find_mut(to);   // 錯誤：第二次可變借用 self
```

因為兩個 `&mut` 不能同時存在（第 3 章規則），即使我們「知道」它們指向不同帳戶，編譯器不知道。
所以先用只讀的 `balance_of`/`find` 驗證，再分兩步修改。第 7 章改用 `HashMap` 後有更好的寫法。

你可能也注意到 `Status::Rejected` 沒有說**為什麼**被拒。餘額不足？帳戶不存在？呼叫者無從得知。這是下一章的主題。

### match 數值

```rust
let tier = match amount.0 {
    0..=999 => "零錢",
    1_000..=999_999 => "一般",
    n if n >= 10_000_000 => "大額（需審核）",
    _ => "中額",
};
```

## 設計筆記：enum 還是 struct + trait？

初學者常問：交易種類用 enum，還是像物件導向語言那樣一個 `Transaction` 介面、三個類別實作？
經驗法則：

- **種類是封閉的、少量的、你會頻繁對它做 `match`** → enum。交易種類就是這樣：你需要在過帳、報表、匯出時對每一種做不同處理。
- **種類是開放的、使用者可能新增、你只透過固定介面操作它** → trait（第 9 章）。例如「儲存後端」：記憶體、檔案、資料庫，核心程式不關心是哪一種。

## 回顧

- enum 的每個變體可以帶不同資料，讓「非法狀態無法表示」
- `match` 必須窮舉，新增變體時所有遺漏處都是編譯錯誤，這是重構的安全網
- `Option<T>` 取代 null：「可能沒有」是型別的一部分，必須處理
- `if let`、`let else`、`matches!` 是 `match` 的簡寫；`map`、`unwrap_or`、`ok_or` 是常用的 Option 轉換
- 生產程式碼避免 `unwrap`，至少用 `expect` 說明理由
