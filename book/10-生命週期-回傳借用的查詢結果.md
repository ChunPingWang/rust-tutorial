# 第 10 章　生命週期：回傳借用的查詢結果

> **場景**：財務要「對帳單」：某帳戶在某段期間的所有交易，可以分頁、算淨變動、找最大一筆。
> 對帳單不該複製交易（一個帳戶可能有幾萬筆），應該借用帳本裡的資料。
> 於是我們第一次需要寫一個**裝著引用的結構體**，編譯器會要求我們標註生命週期。

## Why：為什麼需要生命週期標註

第 3 章的借用規則有一條我們一直沒細談：**引用必須永遠有效，不能指向已釋放的值**。

```rust
let r;
{
    let s = String::from("短命");
    r = &s;         // r 借用 s
}                   // s 在這裡被釋放
println!("{r}");    // r 指向已釋放的記憶體 → 編譯錯誤 E0597: `s` does not live long enough
```

編譯器怎麼知道？因為它追蹤每個引用「借自誰」、「那個誰活到哪裡」。這個「活到哪裡」就是**生命週期（lifetime）**。

在一個函式內部，編譯器看得到所有東西，可以自己推。但跨函式邊界時，它只看簽名，不看實作（這是刻意的：否則改函式內容會影響所有呼叫端的型別檢查，編譯會極慢且錯誤訊息會很遠）。
所以當簽名裡有引用進、引用出，而關係不明顯時，你得告訴編譯器「回傳的引用借自哪個參數」。

對帳單的情境正是如此：`Statement` 裡的 `&Account` 和 `Vec<&Transaction>` 借自帳本。編譯器需要知道：**對帳單活著的期間，帳本必須活著且不被修改**。否則有人在對帳單還在用時把帳戶刪了，對帳單就指向垃圾。這就是舊系統 use-after-free 類型 bug 的編譯期版本。

## What：生命週期參數

### 語法

生命週期參數長得像 `'a`（唸 tick-a），寫在泛型參數的位置：

```rust
fn longer_memo<'a>(a: &'a Transaction, b: &'a Transaction) -> &'a str
```

讀法：「存在某個生命週期 `'a`，`a` 和 `b` 至少活 `'a` 這麼久，回傳值也活 `'a` 這麼久」。
實際上 `'a` 會被推成 `a` 和 `b` 兩者中**較短**的那個。呼叫端：

```rust
let h = ledger.history();
let m = longer_memo(&h[0], &h[1]);   // m 的有效期 = h 的有效期
```

**生命週期標註不會改變任何值活多久。** 它只是描述關係，讓編譯器能檢查。這點很多人誤會。

### 省略規則（elision）

大多數函式不用寫生命週期，因為有三條省略規則：

1. 每個輸入引用參數各自得到一個生命週期
2. 如果**只有一個**輸入生命週期，它就是所有輸出引用的生命週期
3. 如果有多個輸入，但其中一個是 `&self` / `&mut self`，輸出就跟 `self` 一樣

對照前幾章：

```rust
fn largest_memo(memos: &[String]) -> &String          // 規則 2：只有一個輸入
fn account(&self, id: u32) -> Result<&Account, _>     // 規則 3：跟 self
fn statement(&self, ...) -> Result<Statement<'_>, _>  // 規則 3；'_ 是「請套用省略規則」的明寫
```

`longer_memo` 兩個輸入都是引用、沒有 `self`，三條規則都不適用，所以必須手寫。

### 結構體裡的引用

```rust
pub struct Statement<'a> {
    pub account: &'a Account,
    pub entries: Vec<&'a Transaction>,
    pub from_day: u32,
    pub to_day: u32,
}
```

讀法：「`Statement<'a>` 這個型別，裡面的引用都借自某個活 `'a` 的東西，所以 `Statement` 本身不能活超過 `'a`」。

為它寫方法：

```rust
impl<'a> Statement<'a> {
    pub fn net_change(&self) -> Money { ... }                 // 沒有回傳引用，不用管
    pub fn page(&self, ...) -> &[&'a Transaction] { ... }     // 省略規則 3
    pub fn largest(&self) -> Option<&'a Transaction> { ... }  // 明寫 'a！
}
```

`largest` 值得細看。如果寫成 `Option<&Transaction>`，省略規則會讓它變成「借自 `&self`」，也就是借自 `Statement`。
但實際上它借自**帳本**（`'a`），比 `Statement` 活得久。明寫 `'a` 讓呼叫端可以：

```rust
let biggest = stmt.largest();
drop(stmt);                    // 對帳單丟掉
println!("{}", biggest.unwrap());   // 仍然有效，因為它借的是帳本
```

這是生命週期標註**放寬**限制的例子。標註不只是為了讓編譯通過，而是精確描述關係，讓合法的用法被允許。

### 多個生命週期

```rust
pub fn first_involving<'a, 'b>(txs: &'a [Transaction], label: &'b str, account: u32) -> Option<&'a Transaction>
```

回傳借自 `txs`，與 `label` 無關。用兩個參數說清楚之後，`label` 可以是一個很短命的暫時字串：

```rust
let found = {
    let label = format!("查詢 {}", 1003);
    first_involving(h, &label, 1003)     // label 在區塊結尾就死了
};
println!("{:?}", found);                 // 沒問題，found 借自 h
```

如果偷懶寫成 `<'a>(txs: &'a [T], label: &'a str) -> Option<&'a T>`，編譯器會認為回傳值也受 `label` 限制，上面的程式碼就會被拒絕。
實務上 `'b` 可以省略（不寫就是獨立的匿名生命週期）：`fn first_involving<'a>(txs: &'a [Transaction], label: &str, account: u32) -> Option<&'a Transaction>`。

### `'static`

活到程式結束的生命週期。字串字面值是 `&'static str`，因為它存在執行檔的唯讀區：

```rust
pub fn kind_label(kind: &TxKind) -> &'static str {
    match kind {
        TxKind::Deposit { .. } => "存款",
        ...
    }
}
```

兩個常見誤區：

- `T: 'static` 的意思是「`T` 不含任何非 static 的引用」，**擁有所有權的型別（`String`、`Vec`）都滿足**。第 14 章把資料送進執行緒時會看到這個 bound。
- 看到「borrowed value does not live long enough」就加 `'static` 是錯的。那只是把問題換成另一個錯誤。

### 什麼時候結構體該存引用、什麼時候該存值

| 存引用 `&'a T` | 存值 `T` / `String` |
|---|---|
| 短命的視圖：對帳單、解析器、迭代器 | 長命的實體：帳戶、交易、設定 |
| 零複製，效能關鍵 | 需要獨立於來源存在 |
| 使用期間來源不會被修改 | 來源可能被修改或釋放 |
| 不會跨執行緒、不會存進集合長期保存 | 會放進 `HashMap`、送進執行緒、回傳給呼叫端長期持有 |

**預設存值。** 只有在明確知道「這是一個短命視圖」時才存引用。帶生命週期的結構體會「感染」所有用到它的型別（它們也要帶 `'a`），過度使用會讓程式碼難以維護。`Statement` 是合理的：它是一個查詢結果，用完即丟。

## How：對帳單

完整程式碼在 `code/ch10-lifetimes/`，新增 `src/statement.rs`。

### 產生對帳單

```rust
impl Ledger {
    pub fn statement(&self, account_id: u32, from_day: u32, to_day: u32)
        -> Result<Statement<'_>, LedgerError>
    {
        let account = self.account(account_id)?;
        let entries = self.history().iter()
            .filter(|tx| tx.involves(account_id))
            .filter(|tx| (from_day..=to_day).contains(&tx.day))
            .collect();
        Ok(Statement { account, entries, from_day, to_day })
    }
}
```

`Statement<'_>` 的 `'_` 表示「套用省略規則」，也就是跟 `&self` 一樣。這是 Rust 2018 之後的建議寫法：讓讀者一眼看出「這個型別帶生命週期」，又不用取名字。

### 使用與限制

```rust
let stmt = ledger.statement(1001, 1, 2)?;
for tx in stmt.page(0, 10) { println!("  {tx}"); }
println!("淨變動：{} 元", stmt.net_change());
```

對帳單活著時試圖修改帳本：

```rust
let stmt2 = ledger.statement(1002, 1, 4)?;
ledger.open(1004, "新帳戶", Money::ZERO)?;     // E0502: cannot borrow `ledger` as mutable
println!("{}", stmt2.entries.len());
```

這不是編譯器找麻煩。想像 `open` 觸發 `HashMap` 重新配置，`stmt2.account` 就指向舊的、已釋放的位置。
在沒有這個檢查的語言裡，這會是一個偶發、難以重現的崩潰。解法一樣是調整順序：在 `stmt2` 最後一次使用之後再 `open`。

### 零複製解析器

```rust
pub struct MemoParser<'s> { rest: &'s str }

impl<'s> MemoParser<'s> {
    pub fn next_word(&mut self) -> Option<&'s str> {
        let trimmed = self.rest.trim_start();
        if trimmed.is_empty() { return None; }
        let end = trimmed.find(char::is_whitespace).unwrap_or(trimmed.len());
        let (word, rest) = trimmed.split_at(end);
        self.rest = rest;
        Some(word)
    }
}
```

每個 `next_word` 回傳的 `&'s str` 借自**原始字串**（`'s`），不是借自 parser（`&mut self`）。所以呼叫端可以把所有詞收集進 `Vec<&str>`，同時繼續呼叫 `next_word`。
如果回傳型別寫成 `Option<&str>`（省略 → 跟 `&mut self` 綁），第二次呼叫 `next_word` 就會被拒絕（第一個回傳值還借著 `self`）。這是生命週期標註**解鎖合法用法**的第二個例子。

這個模式是所有高效能解析器（JSON、HTTP、CSV）的基礎：serde 的 zero-copy 反序列化就是這樣做的。

## 讀懂生命週期錯誤

```
error[E0597]: `s` does not live long enough
error[E0515]: cannot return reference to local variable
error[E0106]: missing lifetime specifier
error: lifetime may not live long enough
```

| 錯誤 | 意思 | 典型解法 |
|---|---|---|
| E0597 | 引用比被借用的值活得久 | 讓值活久一點（提到外層作用域），或改存值 |
| E0515 | 回傳了對區域變數的引用 | 回傳值（`String` 而非 `&str`） |
| E0106 | 簽名需要標註 | 加 `'a`，想清楚回傳借自誰 |
| may not live long enough | 標註的關係與實際不符 | 檢查是不是把兩個獨立的生命週期寫成同一個 |

E0515 最常見的新手版本：

```rust
fn make_label() -> &str {
    let s = format!("...");
    &s              // s 在函式結束時釋放，引用懸空
}
```

解法不是加生命週期，是回傳 `String`。**函式內產生的新資料，一定要以值回傳。**

## 回顧

- 生命週期是引用的有效範圍；標註只描述關係，不改變任何東西活多久
- 三條省略規則涵蓋大多數函式；兩個輸入引用一個輸出、或結構體存引用時要手寫
- 精確的標註（`Option<&'a T>` 而非 `Option<&T>`）能放寬限制，解鎖合法用法
- `'static` 是「活到程式結束」；`T: 'static` 是「不含短命引用」，擁有型別都滿足
- 預設存值；短命視圖（對帳單、解析器）才存引用

2. 寫 `fn split_memo(memo: &str) -> (&str, &str)`，以第一個空白分成兩半。這需要標註嗎？為什麼？
3. 把 `MemoParser::next_word` 的回傳型別改成 `Option<&str>`，然後試著收集成 `Vec`。讀懂錯誤訊息，再改回來。
