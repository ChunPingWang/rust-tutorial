# 第 4 章　結構體：建立帳戶與交易模型

> **場景**：程式碼審查時同事問：「`amounts[3]` 對應的是 `memos[3]` 嗎？誰保證？」
> 沒人保證。平行陣列是 bug 溫床。我們需要把「一筆交易」「一個帳戶」變成一個整體。
> 同時還有個隱患：金額、帳戶 ID、交易序號全是整數，`balance + account_id` 這種荒謬的程式碼目前是合法的。

## Why：為什麼需要結構體，以及為什麼需要「newtype」

**結構體**的理由不用多說，每個語言都有：把相關的欄位綑在一起。

值得多說的是第二個問題。在大多數語言裡，金額是 `int`、ID 是 `int`、數量也是 `int`，型別系統分不出來。
真實事故：某支付公司曾把「以分為單位」的金額欄位傳給一個以「元」為單位的 API，金額差了一百倍。
兩邊型別都是整數，編譯器無從察覺。

Rust 的習慣做法是 **newtype**：用一個只有一個欄位的結構體把原始型別包起來。
`Money(i64)` 和 `i64` 是兩個不同的型別，不能混用，不能相加，除非你明確定義。這幾乎沒有執行期成本（編譯後就是一個 `i64`），卻擋掉一整類錯誤。

## What：struct、impl、derive

### 三種結構體

```rust
// 具名欄位結構體：最常用
struct Account {
    id: u32,
    owner: String,
    balance: Money,
}

// 元組結構體：欄位沒有名字，用 .0 .1 存取。newtype 就是只有一個欄位的元組結構體
struct Money(i64);

// 單元結構體：沒有欄位，用來當標記（第 9 章 trait 會用到）
struct Audited;
```

### 建立與存取

```rust
let acct = Account {
    id: 1001,
    owner: String::from("王小明"),
    balance: Money(0),
};
println!("{}", acct.owner);

let m = Money(25_050);
println!("{}", m.0);
```

欄位名與區域變數同名時可以簡寫：`Account { id, owner, balance }`。

**結構體更新語法**：以一個現有值為基底建立新值：

```rust
let bob = Account {
    id: 1002,
    owner: String::from("李小華"),
    ..alice           // 其餘欄位從 alice 拿
};
```

注意 `..alice` 會**移動** alice 中沒被覆寫、且不是 Copy 的欄位。這裡 `balance` 是 Copy 所以沒事；
如果 `owner` 沒被覆寫，alice 的 `owner` 就會被移走，alice 之後不能再用。範例裡用 `..alice.clone()` 避開這個問題。

### impl：方法與關聯函式

```rust
impl Account {
    // 關聯函式：沒有 self。用 Account::new(...) 呼叫。慣例叫 new，但不是關鍵字
    fn new(id: u32, owner: &str) -> Account {
        Account { id, owner: owner.to_string(), balance: Money(0) }
    }

    // 方法：第一個參數是 self。用 acct.summary() 呼叫
    fn summary(&self) -> String { ... }         // 借用，只讀
    fn deposit(&mut self, amount: Money) { ... } // 可變借用，會改
    fn into_owner(self) -> String { self.owner } // 取得所有權，呼叫後 acct 不能再用
}
```

`self` 的三種形式直接對應上一章的三種傳參方式：

| 寫法 | 意思 | 什麼時候用 |
|---|---|---|
| `&self` | 借用 | 查詢、計算、格式化。**絕大多數方法** |
| `&mut self` | 可變借用 | 修改狀態：deposit、withdraw |
| `self` | 取得所有權 | 轉換成另一個型別、消耗掉自己。慣例命名 `into_xxx` |

`Self`（大寫）是「目前在 impl 的這個型別」的別名，`fn new() -> Self` 跟 `fn new() -> Account` 一樣，改名時少改一處。

一個型別可以有多個 `impl` 區塊，放在不同檔案也行。

### derive：讓編譯器幫你寫樣板

```rust
#[derive(Debug, Clone, PartialEq)]
struct Account { ... }
```

`#[derive(...)]` 是屬性（attribute），告訴編譯器自動實作某些 trait。現在先把它們當成「開啟某些能力」：

| derive | 開啟的能力 |
|---|---|
| `Debug` | 可以用 `{:?}` 印出來。**幾乎所有型別都該加** |
| `Clone` | 可以 `.clone()` |
| `Copy` | 賦值時複製而非移動。只有所有欄位都是 Copy 才行，而且必須同時 derive Clone |
| `PartialEq` / `Eq` | 可以用 `==` 比較 |
| `PartialOrd` / `Ord` | 可以用 `<` `>` 比較、排序 |
| `Hash` | 可以當 HashMap 的 key（第 7 章） |
| `Default` | 可以 `Account::default()` 得到各欄位預設值 |

`Money` 應該是 `Copy`：它只是一個 `i64`，到處傳來傳去不該觸發移動語意。`Account` 不該是 `Copy`：它有 `String`。
一個判斷標準：**如果這個型別是「值」（數字、座標、金額），就 Copy；如果它代表一個「實體」（帳戶、使用者、連線），就不要。**

### 印出結構體

```rust
println!("{:?}", tx);    // Transaction { id: 1, account_id: 1001, amount: Money(5000000), memo: "十月薪資" }
println!("{:#?}", acct); // 多行縮排版
```

`Debug` 是給開發者看的。給使用者看的格式（例如 `250.50 元`）要實作 `Display` trait，第 9 章會做，現在先用 `format()` 方法代替。

## How：建立 Money、Account、Transaction

完整程式碼在 `code/ch04-structs/`。

### Money

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
struct Money(i64);

impl Money {
    fn from_yuan(yuan: i64) -> Money { Money(yuan * 100) }
    fn cents(self) -> i64 { self.0 }     // self 而非 &self：Money 是 Copy，直接拿值更簡單
    fn format(self) -> String {
        let sign = if self.0 < 0 { "-" } else { "" };
        let yuan = (self.0 / 100).abs();
        let fen = (self.0 % 100).abs();
        format!("{sign}{yuan}.{fen:02} 元")
    }
}
```

derive 了 `PartialOrd, Ord` 之後，`amount > self.balance` 就能直接寫，比較的是內部的 `i64`。

目前 `Money` 還不能直接 `+`，要寫 `Money(a.0 + b.0)`。第 9 章會用 `Add` trait 讓它支援運算子，而且會用 `checked_add` 處理溢位。

### Account

```rust
#[derive(Debug, Clone, PartialEq)]
struct Account {
    id: u32,
    owner: String,
    balance: Money,
}

impl Account {
    fn new(id: u32, owner: &str) -> Account {
        Account { id, owner: owner.to_string(), balance: Money(0) }
    }

    fn summary(&self) -> String {
        format!("#{} {}：{}", self.id, self.owner, self.balance.format())
    }

    fn deposit(&mut self, amount: Money) {
        self.balance = Money(self.balance.0 + amount.0);
    }

    fn withdraw(&mut self, amount: Money) -> bool {
        if amount > self.balance {
            return false;
        }
        self.balance = Money(self.balance.0 - amount.0);
        true
    }
}
```

`withdraw` 用 `bool` 回報成功與否，這是暫時的。它有兩個問題：呼叫者可以忽略回傳值；失敗原因只有一種。第 6 章會用 `Result` 徹底解決。

### Transaction

```rust
#[derive(Debug, Clone)]
struct Transaction {
    id: u64,
    account_id: u32,
    amount: Money,   // 正數存款、負數提款
    memo: String,
}
```

`amount` 用正負號區分存款提款，也是暫時的。「轉帳」需要兩個帳戶 ID，塞不進這個結構。下一章用 enum 解決。

### 使用

```rust
let mut alice = Account::new(1001, "王小明");
let tx1 = Transaction {
    id: gen.next_id(),
    account_id: alice.id,
    amount: Money::from_yuan(50_000),
    memo: String::from("十月薪資"),
};
alice.deposit(tx1.amount);     // Money 是 Copy，tx1.amount 不會被移走
println!("{} 後 → {}", tx1.memo, alice.summary());
```

注意 `alice.deposit(tx1.amount)` 之後 `tx1` 還能用，因為 `Money` 是 Copy。如果 `amount` 是 `String`，這裡就會把 `tx1.amount` 移走，`tx1` 變成「部分移動」狀態。這是把 `Money` 設成 Copy 的實際好處。

### newtype 的保護

把這兩行的註解打開試試：

```rust
// let wrong: Money = 100;                      // expected `Money`, found integer
// let nonsense = alice.balance + alice.id;     // cannot add `u32` to `Money`
```

第二個錯誤正是我們要的：金額加帳戶 ID 是無意義的，現在它是編譯錯誤。

## 設計筆記：欄位要不要公開？

目前所有東西都在 `main.rs`，沒有可見性問題。第 8 章拆模組之後，`Money` 的內部 `i64` 應該是**私有**的：
外部只能透過 `Money::from_yuan`、`.cents()` 存取，這樣我們可以保證「所有 Money 都是合法的」，例如之後若規定金額必須非負，只要在建構函式檢查一處。

## 回顧

- 結構體把相關欄位綑成一個型別；newtype（單欄位元組結構體）讓同為整數的不同概念互不相容
- `impl` 區塊放方法；`&self` 查詢、`&mut self` 修改、`self` 消耗
- `#[derive(Debug)]` 幾乎必加；代表「值」的小型別加 `Copy`，代表「實體」的不要
- `..base` 更新語法會移動非 Copy 欄位
