# ML-4 練習解答

完整可編譯版本：`code/solutions/ml04/`（`cargo run --release`；GPU 加 `--features metal` 或 `--features cuda`）。

## 練習 1：容量與過擬合

```
設定                   epoch  訓練F1  測試F1   AUC    ms
16→8,   60 epoch         60   0.921   0.898  0.989    95
64→32,  60 epoch         60   0.965   0.889  0.990   164
64→32, 200 epoch        200   0.993   0.904  0.990   544
```

訓練 F1 從 0.92 一路到 0.99，測試 F1 停在 0.90 左右。**兩者的差距就是過擬合的程度**：大網路跑久了開始記住訓練集的個別樣本，而不是學規律。
只看測試分數會以為「差不多」，只看訓練分數會以為「大網路好很多」。兩個都要看。

## 練習 2：dropout

```rust
fn forward(&self, x: &Tensor, train: bool) -> Result<Tensor> {
    let mut x = self.l1.forward(x)?.relu()?;
    if train && self.dropout > 0.0 {
        x = candle_nn::ops::dropout(&x, self.dropout)?;    // 訓練時隨機歸零一部分
    }
    // ...
}
```

`forward` 多了 `train: bool`：訓練時丟、推論時不丟。PyTorch 用 `model.train()` / `model.eval()` 切換全域狀態；candle 沒有全域狀態，用參數明寫，更不容易忘記切換。

```
dropout=0    訓練F1 1.000  測試F1 0.887
dropout=0.2  訓練F1 0.965  測試F1 0.889
dropout=0.5  訓練F1 0.949  測試F1 0.922
```

dropout 把訓練 F1 從 1.0 壓到 0.95，測試 F1 反而從 0.887 升到 0.922：**拉近兩者差距就是正則化在做的事**。這份資料上 0.5 最好；更大的網路通常用 0.2 到 0.5，小網路要小心別壓過頭。

## 練習 3：早停

```rust
// 時間順序：訓練集最後 10% 當驗證集
let cut = xtr_all.nrows() - xtr_all.nrows() / 10;
// 每個 epoch 結束
let vloss = bce_with_logits(&model.forward(vx, false)?, vy, 5.0)?.to_scalar::<f32>()?;
if vloss < best_valid - 1e-4 { best_valid = vloss; since_best = 0; } else { since_best += 1; if since_best >= 5 { break; } }
```

```
最多 200 epoch，實際跑了 7；訓練F1 0.910  測試F1 0.889  AUC 0.992  18 ms
```

用驗證集決定何時停，不用手調 epoch。但這次停得太早：patience = 5 對這題太急，第 7 個 epoch 就停，模型還沒學夠。
實務上的調整：patience 10 到 20；保留「驗證損失最低時」的權重（而不是最後一個 epoch 的）；驗證集一樣要按時間切，不能隨機。
早停、dropout、weight decay 三者都是在對抗練習 1 的過擬合，通常一起用。

## 練習 4：GPU

```toml
[features]
metal = ["candle-core/metal", "candle-nn/metal"]
cuda = ["candle-core/cuda", "candle-nn/cuda"]
```

```rust
#[cfg(feature = "metal")]
let dev = Device::new_metal(0)?;
#[cfg(not(any(feature = "metal", feature = "cuda")))]
let dev = Device::Cpu;
```

其餘程式碼一行不改，這是 candle `Device` 抽象的價值。
但對這個模型（305 個參數、batch 256）GPU **不會更快**：每個 batch 的運算只有幾微秒，把資料搬到 GPU、啟動 kernel、拿回結果的固定成本比運算本身大一個數量級。GPU 的優勢在大矩陣乘法（百萬參數、大 batch）。小模型留在 CPU 是正確決定，第一次編譯 Metal 後端也要多花好幾分鐘。

## 練習 5：Python 訓練、Rust 載入

```
檔案裡的 tensor 名稱：["l1.bias", "l1.weight", "l2.bias", "l2.weight", "l3.bias", "l3.weight"]
載入改名後的檔案失敗（預期）：tensor `l1.weight` not found
```

解答用 `safetensors` crate 讀出 candle 存的檔、把 `l1` 改名成 `fc1` 再存一份，模擬 PyTorch 端命名不同的情況。`varmap.load` 用名字對應，找不到就報錯，**不會**靜默載入錯的權重。

Python 端的對應寫法：

```python
from safetensors.torch import save_file
save_file({"l1.weight": model.l1.weight, "l1.bias": model.l1.bias, ...}, "fraud_mlp.safetensors")
```

兩個要對齊的事：名字（Rust 端 `vs.pp("l1")` 決定）與形狀（PyTorch `Linear.weight` 是 `(out, in)`，candle 相同，不用轉置）。
名字不同時，與其改 Python，不如在 Rust 端載入前用 `safetensors` crate 做一次名稱映射，把轉換邏輯留在能寫測試的那一邊。
