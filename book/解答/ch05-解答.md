# 第 5 章練習解答

完整可編譯版本：`code/solutions/ch05/`。

## 練習 1：新增 Fee 變體

```rust
enum TxKind {
    Deposit { account: u32 },
    Withdraw { account: u32 },
    Transfer { from: u32, to: u32 },
    Fee { account: u32 },
}
```

`cargo check` 對第 5 章的程式碼報三個 E0004（non-exhaustive patterns）：`describe()`、`affected_accounts()`、`apply()`，每個 `match self.kind` 的地方都要補。
`involves()` 用的是 `matches!`，**不會**報錯，但邏輯會漏掉 Fee：這是 `matches!` 與萬用 `_` 分支的代價，它們讓你失去窮舉檢查。原則：**對業務 enum 做分支時優先用完整的 `match`，`matches!`、`if let`、`_` 只用在「其餘全部一樣處理」真的成立的時候。**

補法：

```rust
TxKind::Deposit { account } | TxKind::Withdraw { account } | TxKind::Fee { account } => vec![*account],
```

## 練習 2：largest_account

```rust
fn largest_account(&self) -> Option<&Account> {
    self.accounts.iter().max_by_key(|a| a.balance)
}
```

`max_by_key` 在空迭代器上回傳 `None`，剛好是我們要的語義，不需要特別處理空帳本。`Money` derive 了 `Ord` 所以能當 key。

## 練習 3：方法鏈

```rust
fn rich_balance(&self, id: u32) -> Option<Money> {
    self.find(id).map(|a| a.balance).filter(|b| *b > Money(1_000_000))
}
```

- `find` → `Option<&Account>`
- `map` → `Option<Money>`（沒有就維持 None）
- `filter` → 有值但不滿足條件也變 None

三種「沒有」（帳戶不存在、餘額不夠大）在這裡合併成一個 `None`。如果呼叫端需要區分，就不該用 `Option`，該用 `Result` 搭配不同的錯誤（第 6 章）。
