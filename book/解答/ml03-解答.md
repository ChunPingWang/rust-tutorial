# ML-3 練習解答

完整可編譯版本：`code/solutions/ml03/`（`cargo run --release`；多了 `linfa-trees` 與 `linfa-reduction` 兩個相依）。

## 練習 1：手肘法

```rust
for k in 2..=8 {
    let km = KMeans::params(k).max_n_iterations(300).tolerance(1e-5).fit(&acct_ds)?;
    println!("k={k} inertia {:.1}", km.inertia());
}
```

```
k=2  inertia 7.3
k=3  inertia 6.2 （少 15%）
k=4  inertia 5.6 （少 10%）
k=5  inertia 5.2 （少 6%）
k=6  inertia 5.0 （少 5%）
k=7  inertia 4.8 （少 4%）
```

inertia（群內距離平方和）隨 k 單調下降，k 越大永遠越小，所以不能直接取最小。看**下降幅度**：k=3 到 4 之後每多一群只少 5% 左右，手肘大約在 3 到 4。
手肘法是啟發式；silhouette 分數是另一個選擇。最後決定 k 的是「每一群能不能用業務語言解釋」：ML-3 的三群分別是「早上活躍」「下午活躍」「高風險」，說得通。

## 練習 2：群別當特徵

```rust
let cluster_of: HashMap<u32, usize> = ids.iter().copied().zip(clusters.iter().copied()).collect();
// 每筆交易按帳戶查群別，one-hot 成 3 欄接在原特徵右邊
let extra = ...;                                     // n × 3
concatenate![Axis(1), x.view(), extra.view()]        // n × 12
```

```
原 9 特徵      precision 0.981  recall 0.879  F1 0.927   AUC 0.996
加群別 12 特徵  precision 0.981  recall 0.897  F1 0.937   AUC 0.997
```

小幅進步（多抓到一筆）。群別是「帳戶層級的摘要」，把帳戶的長期行為壓成一個類別給交易層級的模型用，是常見的特徵工程手法。

**一個誠實的警告**：這裡的群別是用全部交易算的，包含測試期間，有輕微的資料洩漏（ML-1 談過）。嚴謹做法：只用訓練期間的交易分群，測試期間的帳戶用訓練好的 `kmeans.predict` 指派。

## 練習 3：決策樹

```rust
use linfa_trees::{DecisionTree, SplitQuality};
let tree = DecisionTree::params().split_quality(SplitQuality::Gini).max_depth(Some(5)).min_weight_leaf(5.0).fit(&tr)?;
```

```
深度 ≤ 5 的樹：precision 0.781  recall 0.862  F1 0.820
特徵重要性：log_amount 0.446、amount_vs_acct 0.330、amount_to_balance 0.185、is_night 0.040
```

幾個觀察：

- 樹的 F1（0.82）比邏輯回歸（0.93）低。這份資料的模式偏線性，線性模型剛好；樹要用很多次軸對齊的切分才能逼近一條斜線
- 樹**不需要標準化**：它只比大小，尺度無關。所以解答直接餵原始特徵
- 「特徵重要性」是樹的副產品，和邏輯回歸的權重一樣能回答「模型看什麼」，而且不需要特徵彼此獨立
- 樹的每條路徑是一組 AND 條件（「金額 > X 且 深夜 且 提款」），這就是交互作用。單一棵樹不穩定，實務上用隨機森林或梯度提升樹（Rust 有 `lightgbm` 綏定、`linfa-ensemble`）

決策樹的 target 型別是 `usize`，邏輯回歸是 `bool`，linfa 各演算法對 target 型別的要求不同，看文件。

## 練習 4：PCA

```rust
use linfa_reduction::Pca;
let pca = Pca::params(2).fit(&ds)?;
let proj = pca.predict(&ds);               // n × 2
```

```
前兩個主成分各解釋 28.9% 與 14.9% 的總變異，合計 43.8%
正常交易在 2D 的中心：(-0.23, 0.00)；詐欺的中心：(6.34, -0.03)
```

兩群的中心在第一主成分上差了 6.5 個單位，分得很開；但兩個主成分只涵蓋 44% 的變異，剩下 56% 被丟掉了，所以 2D 散佈圖會看到部分重疊。PCA 是**看資料**的工具（降到 2D 畫圖、找離群值、檢查分群結果），不是分類器；要分類還是用全部 9 維。

一個陷阱：`pca.explained_variance_ratio()` 回傳的是「保留的主成分之間的比例」（兩個加起來 100%），不是「佔全部變異的比例」。解答改用投影後各欄的變異除以總變異（標準化後總變異 = 特徵數）才得到 28.9% / 14.9%。看到「解釋 100% 變異」要先懷疑。

座標存成 CSV（`/tmp/ml03-pca.csv`），用試算表或 Python 畫出來，紅點（詐欺）會集中在右側。
