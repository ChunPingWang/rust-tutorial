# ML-2 練習解答

完整可編譯版本：`code/solutions/ml02/`（`cargo run --release`、`cargo test --release`）。

## 練習 1：pos_weight

```
pos_weight=1    precision 1.000  recall 0.759  F1 0.863   (FP 0  FN 14)
pos_weight=5    precision 0.867  recall 0.897  F1 0.881   (FP 8  FN 6)
pos_weight=20   precision 0.659  recall 0.966  F1 0.783   (FP 29 FN 2)
```

權重越大，模型越「寧可錯殺」：recall 從 0.76 到 0.97，precision 從 1.0 掉到 0.66。
`pos_weight` 和 threshold 的效果類似，都是在移動決策邊界；差別是 `pos_weight` 影響訓練出來的權重本身，threshold 只影響事後的切分。實務上先用 `pos_weight` 處理不平衡到合理範圍（讓模型認真學正例），再用 threshold 微調業務取捨。

## 練習 2：學習率

標準化後的特徵：

```
lr=30    0.150 → 0.033 → 0.029 → 0.027 → 0.026
lr=3     0.214 → 0.081 → 0.060 → 0.050 → 0.045
lr=0.3   0.618 → 0.421 → 0.315 → 0.250 → 0.208
lr=0.01  0.691 → 0.680 → 0.670 → 0.660 → 0.651
```

意外的是連 lr=30 都收斂，而且最快。原因：這個問題是凸的（邏輯回歸 + 交叉熵只有一個最低點），而且特徵已標準化，每個方向的曲率差不多，大步也不會跨過頭。lr=0.01 則是 20 個 epoch 幾乎沒動。

學習率太大的災難要在**尺度沒對齊**時才看得到。同樣的程式餵未標準化的 `train.x`：

```
未標準化 lr=0.3  0.378 → 0.213 → 0.151 → 0.141 → 0.133
未標準化 lr=3    0.875 → 0.875 → 0.288 → 0.188 → 0.113
未標準化 lr=30   0.875 → 0.875 → 0.748 → 0.584 → 0.755
```

lr=3 前八個 epoch 卡在 0.875 不動（`velocity` 這類大尺度欄把 sigmoid 推到飽和區，梯度趨近 0），lr=30 則來回震盪。同樣 20 個 epoch，標準化版本全部收斂到更低的損失。這是 ML-1 堅持標準化的實證。

## 練習 3：mini-batch

```rust
for start in (0..n_total).step_by(batch) {
    let xb = x.slice(s![start..end, ..]);     // 視圖，零複製
    // ...對這一批算梯度、更新一次
}
```

```
batch=全部   第 255 個 epoch 達標，最終損失 0.0851
batch=512    第 25 個 epoch 達標，最終損失 0.0550
batch=64     第 3 個 epoch 達標，最終損失 0.0516
```

達到損失 0.10 所需的 epoch 數：255 → 25 → 3。同樣「看過資料一遍」，batch=64 更新了 75 次，全批次只更新 1 次。代價是每步的梯度只看一小部分資料，比較嘈雜；但嘈雜在非凸問題（神經網路）裡反而有助於跳出局部最低點。ML-4 的 candle 訓練用的就是 batch=256。

解答附了一個測試 `minibatch_converges_faster_per_epoch` 把這個性質固定下來。

## 練習 4：L1

```rust
let l1_grad = self.weights.mapv(|w| if w > 0.0 { 1.0 } else if w < 0.0 { -1.0 } else { 0.0 }) * self.l1;   // sign(w)
let grad_w = xb.t().dot(&residual) / n + &self.weights * self.l2 + l1_grad;
```

L2 的梯度是 `w`（越大拉越用力，但永遠拉不到 0）；L1 的梯度是 `sign(w)`（固定力道，小權重會被拉到剛好 0）。

```
log_amount          +1.014
amount_vs_acct      +0.279
amount_to_balance   -0.000  ← 幾乎為 0
hour_sin            -0.004  ← 幾乎為 0
hour_cos            +0.382
is_night            +0.558
is_withdraw         +0.039
is_transfer         +0.009  ← 幾乎為 0
velocity_24h        +0.447
AUC（L1 後）：0.989
```

三個權重被壓到 0，AUC 從 0.995 降到 0.989。這是「更簡單、更好解釋」與「準確率」的交換，`l1` 的大小控制比例（解答用 0.02；0.05 會壓掉五個特徵、AUC 掉到 0.984）。
被壓掉的 `amount_to_balance` 與 `log_amount` 相關 0.56，資訊重複；`hour_sin` 與 `hour_cos`/`is_night` 重複。但 L1 也可能壓掉業務上有意義的特徵，結果要和領域知識對照，不是機械地刪。

## 練習 5：precision-recall 曲線

```
thr   prec   recall
0.10  0.434  0.966
0.30  0.724  0.948
0.50  0.867  0.897
0.70  0.923  0.828
0.90  1.000  0.724
→ precision ≥ 0.9 下最高 recall = 0.862（thr = 0.62）
```

這張表就是給業務的選項表：「要 precision 0.9 以上（十個攔截九個是真的），最多能抓到 86% 的詐欺，threshold 設 0.62」。業務選一列，工程設一個數字。
threshold 從 0.01 到 0.99 掃一遍只要 99 次 `Confusion::from_scores`，對 1,200 筆資料不到一毫秒。
