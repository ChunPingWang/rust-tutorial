## 練習 1：對帳單端點

```rust
#[derive(Deserialize)]
struct StatementQuery { from: NaiveDate, to: NaiveDate }

#[derive(Serialize)]
struct StatementView {             // 擁有資料，沒有任何引用
    account: u32,
    owner: String,
    from: NaiveDate,
    to: NaiveDate,
    entries: Vec<String>,
    net_change: String,
    balance: String,
}

async fn get_statement(State(state): State<AppState>, Path(id): Path<u32>, Query(q): Query<StatementQuery>)
    -> Result<Json<StatementView>, ApiError>
{
    if q.from > q.to {
        return Err(ApiError::BadRequest(format!("from ({}) 不能晚於 to ({})", q.from, q.to)));
    }
    let ledger = state.ledger.read().await;
    let stmt = ledger.statement(id, q.from, q.to)?;        // Statement<'_> 借用 ledger
    Ok(Json(StatementView {
        account: stmt.account.id,
        owner: stmt.account.owner.clone(),
        entries: stmt.entries.iter().map(|t| t.to_string()).collect(),
        net_change: stmt.net_change().to_string(),
        balance: stmt.account.balance().to_string(),
        from: q.from, to: q.to,
    }))                                                    // 借用在這裡結束
}
```

`Query<T>` 把 `?from=...&to=...` 反序列化成結構體，格式錯誤自動回 400。

**核心衝突**：`Statement<'a>` 借用了 `RwLock` 裡的帳本，而 handler 回傳時鎖已釋放，引用不能活過鎖。解法是在持鎖期間把需要的欄位**複製成擁有的值**（`String`、`Vec<String>`），回應型別不含引用。這是第 10 章「短命視圖」與「跨邊界資料」的界線：視圖在函式內用，跨函式邊界用值。

```rust
use tower::ServiceExt;                 // oneshot

async fn post_json(app: Router, uri: &str, body: &str) -> (StatusCode, serde_json::Value) {
    let req = Request::post(uri).header("content-type", "application/json").body(Body::from(body.to_string())).unwrap();
    let res = app.oneshot(req).await.unwrap();
    let status = res.status();
    let bytes = res.into_body().collect().await.unwrap().to_bytes();
    (status, serde_json::from_slice(&bytes).unwrap_or(Value::Null))
}

#[tokio::test]
async fn deposit_returns_201_and_new_balance() {
    let (status, json) = post_json(app(seed()), "/transactions", r#"{"type":"deposit","account":1001,"amount":"250.50"}"#).await;
    assert_eq!(status, StatusCode::CREATED);
    assert_eq!(json["balances"][0]["balance"], "50250.50");
}

#[tokio::test]

```

`Router` 實作了 tower 的 `Service`，`oneshot` 直接送一個請求進去拿回應，沒有 TCP、沒有埠衝突、可以平行跑。四個測試 0.00 秒。
這就是第 15 章把 `app()` 從 `main` 抽出來的回報。`#[tokio::test]` 幫你建執行器。

## 練習 3：`std::thread::sleep` 的後果

加一個 `/health/slow-blocking` 用 `std::thread::sleep(500ms)`，實測（tokio 預設執行緒數 = 核心數 = 10）：

```
非阻塞 sleep ×3  + 1 快     總耗時 0.52s，快請求等了   1 ms
非阻塞 sleep ×12 + 1 快     總耗時 0.51s，快請求等了   1 ms
阻塞 thread::sleep ×12 + 1 快   總耗時 1.01s，快請求等了 450 ms
```

12 個阻塞請求佔滿 10 個執行緒，快的請求排到第二輪，等了 450ms；總耗時也翻倍。非阻塞版本 12 個慢請求同時進行，快的完全不受影響。
3 個阻塞請求時看不出差別（還有 7 個執行緒閒著），這是為什麼這類 bug 在測試環境常常抓不到，上線負載一高就爆。

## 練習 4：背景存檔

```rust
tokio::spawn(async move {
    let mut ticker = tokio::time::interval(Duration::from_secs(10));
    loop {
        ticker.tick().await;
        let snapshot = state.ledger.read().await.clone();      // 讀鎖只持有 clone 的瞬間
        let path = path.clone();
        let result = tokio::task::spawn_blocking(move || JsonFileStorage::new(&path).save(&snapshot)).await;
        match result {
            Ok(Ok(())) => info!("背景存檔完成"),
            Ok(Err(e)) => warn!(%e, "背景存檔失敗"),
            Err(e) => warn!(%e, "存檔任務 panic"),
        }
    }
});
```

**`spawn_blocking` 還是 `tokio::fs`？** 兩者都行，這裡選 `spawn_blocking`：

- `JsonFileStorage::save` 是同步 API（第 12 章寫的），直接丟到阻塞執行緒池最省事，第 9 章的 `Storage` trait 不用改
- `tokio::fs` 底層其實也是 `spawn_blocking`（作業系統沒有真正非同步的檔案 I/O）
- 序列化 `serde_json::to_string_pretty` 本身是 CPU 工作，放 async 執行緒上大帳本會卡

兩個細節：先 `clone()` 帳本再釋放讀鎖，存檔期間不擋住 API；`spawn_blocking` 的結果是 `Result<Result<..>>`，外層是任務是否 panic。
解答用 `OnceLock` 讓 `main` 拿到 `app()` 內建的 state，正式專案會把 state 建構獨立成函式回傳，而不是用全域。
