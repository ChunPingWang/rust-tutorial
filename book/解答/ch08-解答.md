# 第 8 章練習解答

完整可編譯版本：`code/solutions/ch08/`（第 8 章 crate 加上四題的修改）。

## 練習 1：第二個 bin

新增 `src/bin/stats.rs`，cargo 自動認得 `src/bin/` 下每個檔案是一個執行檔，名稱就是檔名：

```rust
use ledger::{Ledger, Money, Transaction, TxKind};

fn main() {
    let mut ledger = Ledger::new();
    // ...建立資料、過帳...
    let mut counts: BTreeMap<u32, usize> = BTreeMap::new();
    for tx in ledger.history() {
        for id in tx.affected_accounts() {
            *counts.entry(id).or_insert(0) += 1;
        }
    }
    for (id, n) in counts {
        println!("帳戶 {id}：{n} 筆");
    }
}
```

`cargo run --bin stats` 執行。有多個 bin 時 `cargo run` 不加 `--bin` 會要求你指定（除非在 `Cargo.toml` 設 `default-run`）。
bin 用 `ledger::` 引用 lib，和外部套件一樣，只能碰 `pub` 的東西。

## 練習 2：新式模組佈局

```
src/report/mod.rs      →   src/report.rs
src/report/summary.rs      src/report/summary.rs   （不動）
src/report/risk.rs         src/report/risk.rs      （不動）
```

只是把 `mod.rs` 搬到上一層改名，內容一個字都不用改。`mod summary;` 仍然會去找 `report/summary.rs`。
新式佈局的好處：編輯器分頁不會有五個都叫 `mod.rs`。

## 練習 3：from_cents 加檢查

如果直接改成 `fn from_cents(cents: i64) -> Result<Money, _>`，第 8 章 crate 裡約十個呼叫端都要加 `?` 或 `unwrap`，測試也要改。這就是「不變量集中在建構函式」的成本。

解答採取折衷：

```rust
pub const MIN_CENTS: i64 = -1_000_000_000_000;

pub fn from_cents(cents: i64) -> Money {
    Money::try_from_cents(cents).expect("內部建立的金額低於下限，這是程式 bug")
}

pub fn try_from_cents(cents: i64) -> Option<Money> {
    if cents < Money::MIN_CENTS { None } else { Some(Money(cents)) }
}
```

- `from_cents` 簽名不變，給「已知合法」的內部呼叫；違反就 panic，因為那是 bug（第 6 章的區分）
- `try_from_cents` 給外部輸入（第 12 章的 CSV、第 15 章的 API）

這是標準庫的慣例：`Vec::with_capacity` 與 `Vec::try_reserve`、`NonZeroU32::new`（回傳 Option）與 `new_unchecked`。

## 練習 4：文件

```rust
/// 過帳。成功時交易進入歷史紀錄；失敗時帳本**完全不變**。
///
/// # 錯誤
///
/// - [`LedgerError::InvalidAmount`]：金額不是正數
/// - [`LedgerError::AccountNotFound`]：任一涉及的帳戶不存在
/// - [`LedgerError::SameAccountTransfer`]：轉帳的來源與目的相同
/// - [`LedgerError::InsufficientFunds`]：提款或轉帳來源餘額不足
/// - [`LedgerError::Overflow`]：入帳後餘額超過 `i64` 範圍
///
/// 所有檢查都在第一次修改之前完成，因此不會出現「扣了款但沒入帳」的中間狀態。
pub fn apply(&mut self, tx: Transaction) -> Result<(), LedgerError>
```

`# 錯誤`（英文慣例是 `# Errors`）段落列出每個變體與觸發條件，`[`...`]` 是連到該項目的連結。`cargo doc --open` 可以看到效果；`cargo doc` 對壞掉的連結會警告。
標準庫的文件慣例還有 `# Panics`（什麼時候會 panic）、`# Examples`（會被當測試跑，第 11 章）、`# Safety`（unsafe 函式的前提）。
