# 第 16 章練習解答

完整可編譯版本：`code/solutions/ch16/`（第 16 章 crate 加上練習 5 的指標）。

## 練習 1：release 設定的影響

同一份程式碼，兩種 `[profile.release]`：

| 設定 | `server` | `ledger` CLI |
|---|---|---|
| `lto = "fat"` + `strip = true` + `codegen-units = 1` | 1,580,528 bytes（1.5MB） | 733,664 bytes |
| 預設（全部註解掉） | 2,536,944 bytes（2.4MB） | 1,194,240 bytes |

小 38%。三者各自的貢獻：`strip` 最大（符號表通常佔三到四成），`lto` 其次（跨 crate 內聯後刪掉沒用到的程式碼），`codegen-units = 1` 主要影響速度而非大小。
代價是編譯時間：LTO 版的 release 建置約是預設的 1.5 到 2 倍。CI 裡 debug/test 用預設，只有發佈時開 LTO。

## 練習 2：cargo audit

```
$ cargo install cargo-audit
$ cargo audit
    Loaded 1352 security advisories
    Scanning Cargo.lock for vulnerabilities (116 crate dependencies)
（無輸出，exit 0）
```

教材撰寫時（2026 年 10 月）116 個相依 crate 沒有已知漏洞。這個結果有時效性：漏洞是事後揭露的，今天乾淨不代表下個月乾淨。
所以 `cargo audit` 要放在**排程**（每天跑），不只放在 push 觸發的 CI。有漏洞時它會列出 crate、版本、CVE 編號、修復版本，以及是哪個直接相依拖進來的。

## 練習 3：Docker

```
$ docker build -t ledger-server:ch16 .
Successfully tagged ledger-server:ch16
$ docker image ls ledger-server:ch16 --format '{{.Size}}'
50.1MB
$ docker run -d --rm --name ledger-ch16 -p 3016:3000 ledger-server:ch16
$ curl localhost:3016/accounts/1001
{"id":1001,"owner":"王小明","balance":"50000.00","balance_cents":5000000}
$ docker inspect ledger-ch16 --format '{{.Config.User}}'
nonroot
```

50MB 中約 48MB 是 distroless 的 glibc 基底，執行檔只佔 1.5MB。要再小就走 musl 靜態連結 + `FROM scratch`，映像會只剩執行檔。
第二次 `docker build`（只改程式碼）會跳過相依套件的編譯層，從十分鐘變一分鐘，這是 Dockerfile 裡「先用假 main 編譯相依」那幾行的效果。

## 練習 4：clippy pedantic

```
$ cargo clippy --lib --bins -- -W clippy::pedantic
```

對第 16 章的 crate 共 89 個警告，前幾類：

| 數量 | 規則 | 同意嗎 |
|---|---|---|
| 21 + 11 + 3 | `must_use_candidate`：純查詢方法該加 `#[must_use]`，忽略回傳值時警告 | 同意，對函式庫 API 有價值 |
| 13 | `doc_markdown`：文件裡的識別字該用反引號 | 同意，但優先度低 |
| 11 | `missing_errors_doc`：回傳 `Result` 的函式缺 `# Errors` 段 | 同意（第 8 章練習 4 做過一個） |
| 5 | `format_push_string`：`s.push_str(&format!(..))` 可改 `write!(s, ..)` | 同意，少一次配置 |
| 4 | `unreadable_literal`：長數字該加 `_` | 同意 |
| 2 + 2 | `cast_possible_truncation`：`u64 as u32` 可能截斷 | 要看情境；交易 ID 用 `as` 是刻意的，可以在該處 `#[allow]` 並註解 |

pedantic 是「挑剔」等級，預設不開是因為它有不少主觀規則。合理做法：在 `lib.rs` 頂端 `#![warn(clippy::pedantic)]`，然後對不同意的規則個別 `#![allow(clippy::xxx)]`，讓團隊的選擇寫在程式碼裡而不是口頭約定。

## 練習 5：每種錯誤一個指標

```toml
metrics = "0.24"
metrics-exporter-prometheus = { version = "0.17", default-features = false }
```

**放在哪一層**：API 層（`server.rs`），不是 core。理由：core 不該依賴 metrics crate；CLI 不需要指標；「哪些錯誤值得當指標、標籤叫什麼」是部署層的決定。

```rust
fn error_kind(e: &LedgerError) -> &'static str {
    match e {                                              // 窮舉：新增變體時這裡編譯失敗
        LedgerError::AccountNotFound(_) => "account_not_found",
        LedgerError::InsufficientFunds { .. } => "insufficient_funds",
        // ...
    }
}

impl From<LedgerError> for ApiError {
    fn from(e: LedgerError) -> Self {
        metrics::counter!("ledger_errors_total", "kind" => error_kind(&e)).increment(1);
        // ...
    }
}
```

`From<LedgerError>` 是所有業務錯誤進入 API 層的唯一通道（第 15 章），在這裡計數一處搞定。再加一個 `/metrics` 端點吐 Prometheus 格式：

```
$ curl localhost:3000/metrics
ledger_transactions_posted_total 1
ledger_errors_total{kind="insufficient_funds"} 3
ledger_errors_total{kind="account_not_found"} 1
```

`PrometheusBuilder::new().install_recorder()` 回傳一個 `PrometheusHandle`，放進 `AppState`，`/metrics` handler 呼叫 `handle.render()`。
有了這些數字，「餘額不足的比例突然從 3% 跳到 30%」會在儀表板上一眼看到，比翻日誌快得多。這是第 6 章「錯誤是 enum 不是字串」在可觀測性上的回報：字串錯誤沒辦法變成有限的標籤集。
