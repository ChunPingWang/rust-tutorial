## 練習 1：修正稽核

原本的 `Auditor` 拿一個固定的初始總額比對，第一筆交易後就「異常」。修正：記住上次看到的歷史長度，每次檢查時只處理新增的交易，重算預期值：

```rust
struct Auditor {
    ledger: Rc<RefCell<Ledger>>,
    seen: usize,
    expected_total: Money,
}

impl Auditor {
    fn check(&mut self) {
        let ledger = self.ledger.borrow();
        for tx in &ledger.history()[self.seen..] {
            self.expected_total = match tx.kind {
                TxKind::Deposit { .. } => self.expected_total + tx.amount,
                TxKind::Withdraw { .. } => self.expected_total - tx.amount,
                TxKind::Transfer { .. } => self.expected_total,
            };
        }
        self.seen = ledger.history().len();
        let ok = ledger.total_balance() == self.expected_total;
        // ...
    }
}
```

`check` 從 `&self` 變成 `&mut self`，因為它現在有自己的狀態；呼叫端的 `let auditor` 要加 `mut`。
注意 `self.ledger.borrow()` 與 `self.expected_total` 的修改不衝突：前者借的是 `RefCell` 裡的帳本，後者是 `Auditor` 自己的欄位。

## 練習 2：Rule 的序列化

```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum Rule { ... }
```

`Box<T>` 對 serde 是透明的，JSON 裡看不到它。輸出：

```json
{
  "or": [
    { "and": [ { "amount_above": 1000000 }, "is_withdraw" ] },
    { "and": [ { "involves": 1002 }, { "memo_contains": "現金" } ] }
  ]
}
```

一個陷阱：`#[serde(tag = "op")]`（第 12 章 `TxKind` 用的內部標籤）**不能**用在 tuple 變體（`And(Box<Rule>, Box<Rule>)`），編譯期直接報錯。這裡用預設的外部標籤形式。想用內部標籤，變體要改成具名欄位 `And { left: Box<Rule>, right: Box<Rule> }`。

這讓風控規則可以存在設定檔或資料庫裡，不改程式就能調整。

## 練習 3：RefCell 的 panic

會 panic 的寫法：

```rust
let l = shared.borrow();                 // Ref 活著
let bal = l.balance_of(1001);
shared.borrow_mut().apply(tx);           // panic: already borrowed: BorrowMutError
```

修法：讓讀的借用在寫之前結束。最乾淨的是小區塊：

```rust
let bal = {
    let l = shared.borrow();
    l.balance_of(1001).unwrap()
};                                        // l 在這裡釋放
shared.borrow_mut().apply(tx).unwrap();   // OK
```

或者 `drop(l)`。原則與第 3 章的 NLL 相同，只是 `RefCell` 的借用**不會**在最後一次使用時自動結束，而是到 `Ref` 被 drop 為止（它是一個值，有 `Drop`）。所以 `RefCell` 的借用要刻意縮短作用域。

## 練習 4：Cow

```rust
pub fn normalize_memo(memo: &str) -> Cow<'_, str> {
    let trimmed = memo.trim();
    let has_double_space = trimmed.split(' ').any(|w| w.is_empty());
    if trimmed.len() == memo.len() && (trimmed.is_empty() || !has_double_space) {
        return Cow::Borrowed(memo);       // 已經乾淨，零配置
    }
    Cow::Owned(trimmed.split_whitespace().collect::<Vec<_>>().join(" "))
}
```

測試用 `matches!(r, Cow::Borrowed(_))` 驗證「乾淨輸入沒有配置」。
第一版漏了空字串：`"".split(' ')` 產生一個空字串元素，被誤判為有連續空白，變成 `Owned`。測試 `empty_and_single_word` 抓到了它。邊界案例（空、單一元素、全空白）永遠值得一個測試。

`Cow` 適合「大多數輸入不需要修改」的正規化函式：備註、路徑、使用者名稱。每筆交易都複製一個 `String` 很浪費，但只有 5% 需要修改。
