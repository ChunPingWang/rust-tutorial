## 練習 1：export 子命令

`csv` crate 不支援 `#[serde(flatten)]` 的 enum（CSV 是平的，沒有巢狀），所以要一個平面的中介型別：

```rust
#[derive(Serialize)]
struct HistoryRow<'a> {
    id: u64,
    date: NaiveDate,
    #[serde(rename = "type")]
    kind: &'static str,
    account: Option<u32>,     // None 會寫成空欄位
    from: Option<u32>,
    to: Option<u32>,
    amount: String,           // "1000.00"，用 Money 的 Display
    memo: &'a str,            // 借用，不複製
}

fn cmd_export(path: &PathBuf, out: &PathBuf) -> Result<()> {
    let ledger = load_ledger(path)?;
    let mut wtr = csv::Writer::from_path(out)?;
    for tx in ledger.history() {
        let (kind, account, from, to) = match tx.kind {
            TxKind::Deposit { account } => ("deposit", Some(account), None, None),
            TxKind::Withdraw { account } => ("withdraw", Some(account), None, None),
            TxKind::Transfer { from, to } => ("transfer", None, Some(from), Some(to)),
        };
        wtr.serialize(HistoryRow { id: tx.id, date: tx.date, kind, account, from, to, amount: tx.amount.to_string(), memo: &tx.memo })?;
    }
    wtr.flush()?;
    Ok(())
}
```

輸出的 CSV 與 `import` 讀的格式相同，所以 `import → export → import` 可以來回。這是第 12 章「外部格式用中介型別」原則的輸出端版本：`HistoryRow` 是 `TxRow` 的鏡像。

`memo: &'a str` 借用交易的字串，整個匯出過程零複製（第 10 章）。

## 練習 2：千分位

```rust
fn from_str(s: &str) -> Result<Self, Self::Err> {
    let cleaned: String = s.trim().chars().filter(|&c| c != ',').collect();
    // ...其餘不變
}
```

**改 `Money::from_str` 而不是 `money_from_str`**。理由：「1,500.00」是人類寫法的一部分，命令列參數、設定檔、CSV 都會遇到；`money_from_str` 只是 serde 到 `FromStr` 的橋，不該有自己的解析邏輯。改在一處，所有入口都受惠。

CSV 裡 `"1,500.00"` 會被引號包起來，`csv` crate 處理引號，交給我們的已經是 `1,500.00`。

## 練習 3：--verbose 全域選項

```rust
struct Cli {
    #[arg(long, global = true)]
    verbose: bool,
    #[command(subcommand)]
    command: Command,
}
```

`global = true` 讓 `ledger import --verbose ...` 與 `ledger --verbose import ...` 都合法。值在 `cli.verbose`，傳給需要的子命令函式。
解答只在 `import` 用它印出成功的交易；真實工具會把它接到 `tracing` 的日誌層級。

## 練習 4：cargo tree

```
$ cargo tree -e normal --prefix none | sort -u | wc -l
39
```

第 12 章的七個直接相依總共拖進 39 個 crate。各自的子樹大小：

| 直接相依 | 子樹 crate 數 |
|---|---|
| clap | 19 |
| chrono | 13 |
| serde | 9 |
| thiserror | 8 |

clap 是最大的來源：它的 derive 巨集、終端機顏色、錯誤建議（拼字相似度）各是獨立 crate。如果只需要最簡單的參數解析，`clap` 可以關掉 default features 只開 `derive`，或改用更小的 `pico-args`/`lexopt`。
`cargo tree -d` 另外會列出被不同版本重複引入的 crate，那是編譯時間與執行檔大小的浪費來源。
